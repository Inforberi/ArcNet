# ADR-006: ограниченная телеметрия и локальное восстановление

Дата: 2026-11-05. Принято для исходников и локальной проверки. Контрольный профиль пользователя — 512 МиБ/1 vCPU, не подтверждённый minimum для VPN.

## Мониторинг

Один `metrics.Sampler` принадлежит HTTP server, один — agent lifecycle. Контроллер собирает ресурсы каждые 30 секунд; агент передаёт расширенный снимок не чаще минуты успешного цикла (фактический интервал может быть больше из-за jitter/других операций). Heartbeat остаётся отдельным, со своим 20-секундным базовым интервалом. Метрики кешируются на 5 секунд, нет глобального mutable singleton или sampler на каждую вкладку.

Новый optional bearer endpoint `/api/nodes/telemetry`, wire v1, сохраняет совместимость неизменённого heartbeat. Старый контроллер даёт 404 — новый агент продолжает работу; старые агенты отображаются с частичными данными. Receipt timestamps задаёт контроллер, принимается ограниченное окно часов ±300 секунд. Ресурсы устаревают через 180 секунд; потеря heartbeat через существующие 75 секунд отдельно скрывает живые показатели. Snapshot не повышает VPN-probe, не делает ACK и не публикует маршруты.

ОС предоставляет накопительные счётчики, не «мгновенную нагрузку»: CPU считается по двум `/proc/stat` снимкам без guest double count, idle включает iowait; сеть — по дельте счётчиков интерфейсов маршрута по умолчанию. Loopback/типовые tunnel/veth/bridge-интерфейсы не суммируются повторно. Epoch, смена интерфейсов, сброс счётчиков или большой разрыв обнуляют пригодность дельты, а не создают spike. Контроллер пересчитывает удалённую скорость из counters, не доверяет присланному `bytes/s`. Другие показатели остаются утверждениями аутентифицированного агента, без удалённой аттестации.

SQLite хранит последний снимок каждой минуты: до 120 минут на node, общий cap 32768 строк. Очистка нужна при новой minute bucket, а не каждом обновлении существующей. Локальный writer ограничен 30 секундами, удалённый — минимумом 10 секунд для защиты API. Одна горутина принадлежит `serve`, завершается до закрытия DB; не создаёт subprocess для ресурсных метрик. Чтение дашборда не пишет наблюдения в DB. Ошибка фонового writer передаётся флагом, текущие доступные показатели остаются видимыми.

Вместо новой SSE-инфраструктуры выбран polling с явными лимитами: snapshot/fleet каждые 30 секунд, история раз в минуту, фоновое обновление скрытой вкладки отключено. `history=0` исключает чтение/пересылку history при частом snapshot. В UI по 20 карточек с поиском/раскрытием; SVG максимум на 120 точек, без animation loop и chart dependency. Решение не объявляется быстрее SSE без сравнительного теста.

Показатели host/namespace не равны VPN traffic/user counters; OS `/proc` в контейнере может описывать VM/namespace, не cgroup budget. Диск — filesystem каталога данных, `Bavail` для непривилегированного пользователя. Неизвестное/первый delta — null, не 0. История не переносится в VPN-state backup; при замене identity удаляется, чтобы старые наблюдения не выглядели новой проверкой.

Для dashboard user counts используется SQL aggregate, без чтения UUID/subscription tokens. Для password KDF — отдельный per-server admission limit 1; стоимость хеша не уменьшена ради старого CPU. Обычные сессии не пересчитывают пароль на каждом API запросе. Административные ответы имеют `Cache-Control: no-store`.

## Восстановление

Root-wrapper имеет фиксированные CLI commands и drops privileges к `arcvpn` до DB access. Core recovery требует service identity, ожидаемую директорию и существующую безопасную DB. Обычная смена пароля сохраняет активную MFA; отдельный флаг явно снимает второй фактор. Незавершённый enrollment MFA отменяется в обоих случаях. Отзыв сессий/пароль/MFA/audit — одна SQLite-транзакция без изменения VPN-state. Ключи и существующие пароли не показываются.

Отклонены: постоянный тяжёлый metrics service; фальшивый load×50 как CPU%; 0 вместо unknown; RTT/heartbeat как VPN proof; пароль в argv; default reset MFA; root database recovery; произвольные shell/systemd commands.
