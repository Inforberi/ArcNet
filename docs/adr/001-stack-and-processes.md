# ADR-001: компактный Go-монолит и статический React UI

**Статус:** принято для стартового проектирования. **Дата:** 2026-11-03.

## Решение

Go + SQLite WAL + React/TypeScript/Vite + React Router Data Mode + TanStack Query + Tailwind/shadcn/ui. React собирается в статику, Go раздаёт файлы и API. Xray — отдельный процесс. Standalone локально не запускает agent. Удалённый VPS использует Go Agent с исходящим защищённым каналом. systemd — основной способ запуска; Podman — опция.

## Почему

Панель требует интерактивных таблиц, графиков, форм и сложных маршрутов. SSR/Node.js на VPS не приносит необходимой ценности. Go-монолит и SQLite не требуют отдельного DB/queue процесса. Копируем из референсной Go-архитектуры принципы ownership/lifecycle, но не инфраструктуру другого приложения.

## Альтернативы

- Next.js SSR: избыточный серверный слой при уже существующем Go API.
- Next.js static export: допустим, но сложнее ограничения для динамической админки; преимуществ в нашем сценарии недостаточно.
- Svelte: возможен, но выбран React из-за знакомой структуры и доступности библиотек/ИИ-поддержки.
- HTMX/Go templates: отлично для простой админки, меньше подходит для всего объёма интерактивности.
- Podman обязательно: усложнит доступ к сети/привилегированным сетевым операциям; использовать опционально.

## Критерий пересмотра

Пересматривать решение только после конкретной технической проблемы или измерения, а не общих тезисов о «самом быстром» фреймворке.
