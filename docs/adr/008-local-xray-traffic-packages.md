# ADR-008: подтверждённый расход и локальные пакеты Xray

2026-11-05. Реализовано для локального Xray; не приёмка VPN/VPS и не универсальный биллинг. Деньги не учитываются. Требование пользователя — гигабайты пакета, upload+download, 1 ГБ = 10^9 байт.

## Ответственность

- `internal/usage` — диапазоны, монотонные counters/epoch, пакет/период, причины ограничения и переносимый accounting state.
- `internal/xray/statistics.go` — один фиксированный bounded `xray api statsquery`, без shell, с `-reset=false`, таймаутом и лимитом stdout 8 МиБ. Identity сверяется с конфигурацией, конфигурация и socket epoch проверяются до/после запроса. На ошибке нет подстановки нулей.
- `internal/store/usage*.go` — одна транзакция SQLite для checkpoints, сумм и минутных списаний. Никаких Redis/нового фонового сервиса, DTO отчёта из браузера или arbitrary agent RPC.
- `internal/app/usage.go` — единственный lifecycle collector и reconcile доступа, сериализация с существующими мутациями/restore через `App.mu`. `cmd/arcvpn` владеет запуском/остановкой до закрытия DB.
- HTTP — чтение usage/debits и session+CSRF PUT пакета; React `PackageDialog`/`UsageSummary`/модель, композиция `Users` из существующей дизайн-системы.

## Граница источника

Управляемый локальный Xray получает только `StatsService` на `$DATA_DIR/xray-stats.sock`. TCP API, HandlerService и конфигурационный RPC не включаются. Каталог должен быть private 0700, socket — без групповых/прочих прав и с владельцем effective UID панели. Установочный unit уже имеет `User=arcvpn`, `UMask=0077`, доступ к каталогу данных. Публичные API/подписки не содержат этот socket, counter credentials или UUID из checkpoints.

Эпоха — device/inode/mtime приватного Unix-сокета. Не определяется по неточному `now-uptime`. Изменившийся socket/config во время запроса делает весь результат непригодным. Привязка к UUID не даёт импортировать счётчик другого пользователя под тем же числовым ID. Публичный usage API не читает/не возвращает пользовательские ключи.

Проверена конкретная версия **Xray v26.6.1 Linux arm64**. Установщик сейчас не закрепляет эту версию; совместимость старых/будущих версий не заявлена. Неподдерживаемая конфигурация отклоняется `xray run -test` с существующим rollback; недоступный StatsService не позволяет включить конечный пакет. Старые managed-node renderer/allowlist не расширялись и не получили API.

## Списание и разрывы

Периодический запрос примерно раз в 5 секунд, отдельно от изменяемой частоты OS dashboard. Нет коллектора на вкладку и нет API приёма произвольного расхода. В одном пакетном запросе учтены оба фиксированных email namespace базового VLESS и XHTTP, включая нулевые неиспользуемые streams. Произошедшая передача суммируется по двум направлениям; host network counters не используются.

Checkpoint и суммы обновляются атомарно. Повтор/старое наблюдение не списывает байты вновь, регрессия внутри эпохи и поздний replay старой эпохи отклоняются. Новый подтверждённый процесс считается от нуля, старые суммы сохраняются. При отсутствии активности одинаковые checkpoints записываются не чаще минуты, source liveness обновляется независимо.

До управляемого apply снимается доступный расход; после успешного apply фиксируется новая наблюдаемая эпоха. Даже такой переход может потерять небольшой хвост между последним чтением и остановкой процесса: `incomplete=true` виден в UI, остаток подписан «по учёту», полный subscription usage header не публикуется. Точность до байта не обещается. Неожиданный restart ставит дополнительно `needs_review`; конечные пакеты закрываются до явного нового периода или снятия лимита. Восстановление архива не снимает этот флаг.

Безлимитные пользователи продолжают работать при отсутствии counters. Для конечного пакета source считается свежим до 20 секунд; unknown/stale → fail-closed намерение и повторный apply. Реальное прекращение сессий требует рабочего root helper/Xray/systemd. При отказе helper трафик ранее применённой конфигурации может продолжаться: показываем `apply_failed`, отклоняем новые экспорты по политике, повторяем reconcile; не называем это подтверждённой блокировкой. Фиксированного byte overshoot или жёсткого времени отключения без стенда/нагрузки не заявлено.

## Границы первой реализации

Конечные пакеты поддерживаются **только для локального Xray без зарегистрированных нод и активных Hysteria2/WG/AWG**. Это gate возможности учёта, не удаление протоколов: безлимитный прежний сценарий сохраняется. Нельзя добавить/включить неподдерживаемый движок при конечных пакетах или развернуть ноду с ограниченными пользователями. Срок действует на локальные генераторы всех движков; распределённый срок запрещён до ACK/revoke контракта. Создание конечного пакета/нового периода требует свежего источника.

Редактор CAS не сбрасывает расход при обычной смене квоты/срока. Явный новый период сохраняет credentials/checkpoints и обнуляет только расход периода. Повтор запроса со старой версией даёт 409, не второй reset. Ошибка apply не откатывает уже измеренные байты; UI различает saved/pending/applied/unverified. Удаление с неуспешным apply атомарно восстанавливает пользователя, protocol credentials и весь его accounting state.

Minute debit history: до 90 дней, глобально до 65536 записей, API возвращает последние 60 минутных записей пользователя. Сумма периода не зависит от очистки истории. Backup v6 переносит пакеты/checkpoints/списания; лимит encrypted JSON 64 МиБ (plaintext до 32 МиБ). На том же UUID restore не уменьшает известный расход текущего периода и не возвращает старый checkpoint. Legacy v1–v5 сохраняет surviving accounting. После restore liveness сбрасывается до новой настоящей проверки. История/период — не денежные операции.

## Остаток

Сбор/исполнение для Hysteria2, WG/AWG и нод, per-device credentials/отзыв/лимит устройств, auto renewal periods, quota UX при недоступном runtime, независимый первый протокол и stage5 каскад/failover/publish остаются отдельными работами. Нужны VPS-тесты действующего отключения TCP/UDP, рестартов, частичных apply, времени реакции и переноса на другой хост. Ни IP-count, ни Xray online IP map не объявлены числом физических устройств.

Первичные основания: [Xray v26.6.1 StatsService/QueryStats](https://github.com/XTLS/Xray-core/blob/v26.6.1/main/commands/all/api/stats_query.go), [Unix API listener](https://github.com/XTLS/Xray-core/blob/v26.6.1/app/commander/commander.go), [policy user counters](https://github.com/XTLS/Xray-core/blob/v26.6.1/infra/conf/policy.go). Context7 использован для первичного поиска; детали CLI/socket дополнительно проверены по этому исходному тегу и реальному бинарнику.
