# ADR-002: ноды применяют версии желаемого состояния

**Статус:** проектное решение. **Дата:** 2026-11-03.

## Решение

Центральная панель хранит desired revision, а ноды — last known good revision. Узлы не получают произвольные shell-команды. Через защищённое исходящее соединение выполняются строго типизированные операции, контролируемый apply и отчёт о текущем состоянии.

## Причина

Позволяет пережить отключение панели, избежать скрытого рассогласования, видеть ошибки и откатывать конфигурации. Управление локальным Xray переиспользует тот же контракт применения, но без сетевого агента.

## Ограничения

Между независимыми VPS нет общей атомарной транзакции. Команды должны иметь idempotency key и подтверждённое состояние. Потеря связи — не подтверждение успеха.

## Реализация 0.6.0→0.6.1 (частично, 2026-11-04)

Агент открывает исходящий HTTPS к controller origin с валидацией серверного TLS и индивидуальным bearer-secret. Это **не mTLS**; текущая модель двусторонней проверки: TLS-сертификат сервера + scoped bearer клиента. Enrollment — однократный токен, новый секрет — по 2-phase rotation; отзыв hash в SQLite блокирует агента. Команды `apply_xray_v1` содержат version, operation ID, desired revision, SHA256 и валидируемый Xray JSON. Привилегированная часть ограничена Unix socket с SO_PEERCRED и root-owned receipt. Повтор одной ревизии использует тот же operation ID; после восьми безрезультатных доставок требуется ручной retry. `vpn_probe=unknown` остаётся unknown до внешнего handshake, `published=false`. Реальная отработка TLS/SSH/systemd/VPN требует VM/внешней проверки.


### Дополнение 0.6.1: версии и SSH-операции

В heartbeat передаётся `protocol_version=1`; контроллер не отправляет типизированное применение, если агент не сообщил совместимость. Настоящее mTLS по-прежнему отсутствует. Отдельный SSH lifecycle (`install`, `remove`, `upgrade`) не заменяет цикл reconciliation: SSH-key pinning, root-owned install marker, явный approval и SQL journal; `upgrade` требует Ed25519-подписанный релиз строго **новее** в рамках семейства `0.6.x`, выполняет локальную проверку Xray перед бинарной заменой, пытается вернуть оба бинарника при отказе systemd. Успешное локальное обновление **не** доказывает работоспособность VPN с клиентской сети.

Состояние `STAGE4_SOURCE_IN_PROGRESS` обусловлено отсутствием React E2E, VM/VPS и внешнего VPN-handshake. Документация [0.6.1](../release-0.6.1-stage4-continuation.md) устанавливает точный следующий gate.
