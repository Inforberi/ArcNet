# ADR-004: единый черновик маршрута и переносимый backup v4

Статус: принято в рамках разрешённого блока 2026-11-05.

## Решение

React Flow отображает и редактирует существующий `RoutePolicy`; отдельной бизнес-модели графа или нового runtime нет. Форма и схема меняют один черновик, сервер повторно проверяет граф в SQLite-транзакции. Сохранение остаётся отдельным действием, связи не публикуются.

React Flow выбран для соединения карточек, zoom/pan и управления с клавиатуры. Статический SVG подходит для просмотра, но потребовал бы самостоятельной реализации интерактивности. Библиотека загружается лениво, карточки мемоизированы, нет анимации трафика или непрерывного физического layout. Дополнительные карточки ограничены поиском; участники текущего маршрута всегда видимы.

Backup получает новую версию 4 вместо незаметного изменения v3. v4 заменяет черновики вместе с реестром нод, проверяет ссылки/циклы и увеличивает CAS-версии. Старые v1/v2/v3 сохраняют текущие черновики; если замена нод разрывает ссылки, вся транзакция отклоняется. Успешный import не означает успешный VPN.

Нода с зависимыми черновиками не удаляется. Проверки выполняются при отзыве и при постановке SSH-удаления в очередь; активная операция удаления блокирует добавление ссылки. Не производится скрытого удаления пользовательских маршрутов или автоматической замены выходов.

## Последствия

Появилась frontend-зависимость, но отсутствуют новые сервисы на VPS. Глобальная проверка циклов остаётся консервативной: независимые встречные каналы и балансировка требуют нового контракта. Реальный staged apply/ACK/egress/publish находится за отдельным gate этапа 5.
