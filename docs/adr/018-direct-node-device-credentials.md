# ADR-018: синхронизация устройств на прямых TCP/REALITY-нодах

2026-11-06. Законченный source-блок device credentials, **не удалённый byte accounting/finite quotas**.

Helper сообщает отдельный device_protocol1 через прежний read-only capability query; агент переносит его в authenticated heartbeat. Старый protocol1/cascade capability не заменяет поддержку устройств. Controller допускает device mode только для уже подготовленных прямых managed TCP профилей с актуальной capability, без каскадной lease и конечных пакетов. Список активных credentials для remote device mode ограничен512 для ограниченного RPC payload, не как benchmark/max users.

SQLite credential_clock/триггеры users+user_devices дают монотонную generation даже при восстановлении/прямом repository mutation. Новый node_credentials хранит generation и конкретный operation ID. На authenticated node poll App под mutation lock читает clock и строит список UUID из device records; общий UUID managed-пользователя не включается. Новый typed `apply_xray_devices_v1` использует прежний узкий VLESS validator/atomic apply/receipt; произвольных JSON/shell/paths нет.

Queue проверяет generation и endpoint повторно в SQLite-транзакции. ACK обновляет applied_generation только для совпадающего текущего operation ID; новое устройство/его direct URI/QR не выдаётся до ACK всех нод. Повтор операции/после рестарта использует прежнюю node operation identity. Failed operation того же generation не создаёт бесконечно новые IDs: нужен явный retry. Изменение только metadata лимита, дающее прежний config digest, фиксируется по прежнему подтверждённому config без restart. Рендер выполняется при изменении generation, не при каждом poll. Новый постоянный worker не добавлен.

Отзыв сохраняет monotonic revoked_at независимо от доступности helper; локальный reconcile выполняется как прежде, remote convergence происходит при следующем poll/ACK. UI remote_pending не называет сохранение завершённым disconnect. Старый уже выданный UUID может продолжать работать на недоступной ноде до применения; это видимое pending/unknown, не обещание мгновенного отзыва. Новые credentials при отсутствии capability заблокированы. Физические устройства не аттестуются.

Backup v11 переносит node identities + device state; v1–v10 продолжают читаться, old schema не получает неподдерживаемый новый shape. Runtime receipts/capabilities/generations/node Reality private profiles не входят в portable archive. После restore создаются inert node_control rows, без applied/published/доверия прежним ACK. Revocations/high-water сохраняются; для полного управления нужны существующая защищённая SQLite+node-control.key/OS snapshot либо отдельное восстановление node control. Portable device metadata не называется готовым восстановленным VPN. Не считать node rebind/REALITY/systemd принятыми без VM/VPS.

Открыто: device mode на cascade-owned нодах, remote Hysteria/WG профили, приём/аттестация удалённых counters, per-node budget/enforcement глобального пакета при обрыве контроллера, автоматический bootstrap нового узла после включения device mode. До полного учёта/исполнения `CheckPackageCoverage` по-прежнему запрещает конечные remote quotas/expiry; этот запрет не снят. [Проверки](../testing/local-results/stage5-2026-11-06-remote-devices.md).
