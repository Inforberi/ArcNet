# ArcVPN 0.3.0-preview: повторная локальная проверка

**Дата:** 2026-11-04. **Статус:** локально проверенный прототип; **НЕ production-ready**.

## Реально добавлено

- Регистрация удалённых агентов по одноразовому токену на 10 минут, hash-only в SQLite; отказ от повторного использования.
- `arcvpn-core node-register` и `node-agent`, отправка системных метрик на контроллер исходящим HTTPS с проверкой сертификата. Heartbeat каждые 20 секунд, отображение онлайн-статуса через 75 секунд отсутствия сигнала, отзыв доступа агента из UI.
- Выдача из UI команды `curl ... | sudo bash ...` для установки **только агента мониторинга**. Скрипт проверяет SHA-256 скачанного бинарника, регистрирует ноду и создаёт systemd-сервис. На удалённой машине не устанавливает Xray, не управляет UFW и не создаёт VPN — это следующий этап.
- Тёмная/светлая тема по cookie `arcvpn_theme` (обычная неаутентификационная cookie), включая компактную мобильную навигацию; строгие cookies сессии остаются `HttpOnly`.
- Локальный CLI `admin-reset` для восстановления доступа с генерацией нового пароля и атомарным отзывом ВСЕХ административных сессий; команда доступна в терминальном меню.
- Обновлены исходники React + Vite с экранами нод и переключением темы. **Production-сборка React по-прежнему не подтверждена:** npm-зависимости недоступны в среде. В исполняемом файле работает встроенный JS-интерфейс.
- Ранее реализованные функции 0.2 сохранены: VLESS + Reality (генератор конфигурации), SQLite, пользователи, подписки, QR, экспорт/импорт ArcVPN, лимит логов Go-панели.

## Критически отсутствует

- Автоматическое развёртывание Xray и всех настроек на удалённых нодах, SSH-provisioning через UI, синхронизация Inbound/Outbound/пользователей между VPS.
- Автоматические каскады, failover входных/выходных соединений, проверки протокола с клиентской стороны.
- Серверные Hysteria2, WireGuard и AmneziaWG, реальные TLS-подключения клиентов по ним и их импорт в VPN-приложения.
- Управление UFW из UI, TLS hardening всей инфраструктуры, 2FA, устройства/HWID, глобальный учёт трафика.
- Ротация Xray и системных логов в UI. Текущий лимит 500 MiB относится только к файлам Go-панели.
- Импорт 3x-ui, поддержка нескольких независимых протоколов в одной подписке, автоматическое переключение клиентов между профилями.
- Испытания на реальном VPS: systemd, firewall, ACME, выпуск/продление IP TLS сертификата, реальные UDP/TCP соединения, работа Happ, сетевые блокировки.
- Проверенная сборка React (нет npm dependencies), независимый security audit, E2E failover и подтверждённый бюджет 1 vCPU/1 ГБ.

## Блокирующие условия production

1. Проверить оригинальную установку и откат на изолированных Ubuntu/Debian VPS с возможностью аварийного доступа через консоль провайдера.
2. Довести удалённую ноду до настоящего управляемого Xray, затем добавить корректные каскады и резервирование.
3. Поддержать каждый запрашиваемый протокол серверным движком и клиентскими тестами, а не макетным списком.
4. Реализовать защиту всех системных операций, централизованный state reconciliation, 2FA, безопасный импорт конфигураций 3x-ui.
5. Выполнить продакшен-сборку React со lockfile, браузерный E2E через реальный HTTPS, контраст/адаптивы.
6. Протестировать CPU/RAM и длительные отказоустойчивые сценарии при целевой конфигурации 1 vCPU / 1 ГБ.

**Не устанавливать поверх рабочего 3x-ui. Не использовать эту сборку для повседневного VPN.**
