# ArcVPN 0.5.0 — этап 3, исходники для локальной разработки

**Дата:** 2026-11-04. **Статус:** кодовый кандидат, **не production**.

## Реализовано в этом блоке

1. **TOTP 2FA администратора:** новая таблица `admin_mfa`, создание временного секрета на 10 минут, URI и QR для Authenticator, подтверждение кодом, вход по паролю+TOTP, защита от повторного кода, завершение всех сессий при активации/отключении; отключение только после повторного ввода пароля и TOTP. CLI `admin-reset` сбрасывает MFA и сессии одновременно.
2. **Журналы ArcVPN:** в React можно читать последние строки panel/Xray/Hysteria/WireGuard/AWG через ограниченный системный обработчик. Установлен строгий allowlist имён служб, нельзя указать произвольный systemd unit или исполняемую команду. Установщик создаёт собственный `systemd-journald@arcvpn` namespace с лимитом 200 МиБ, а UI умеет изменять его бюджет 50–1024 МиБ через узкую команду root helper. Глобальная конфигурация журнала ОС/SSH не меняется. Реальное поведение systemd namespace и обновления бюджета пока не проверено на VPS.
3. **Лимит логов панели:** ротатор дополнительно проверяет отсутствие симлинков и ограничивает суммарный размер файлов при запуске/смене бюджета, а не только при новом событии. При резком уменьшении лимита старые файлы могут быть удалены.
4. **Зашифрованные локальные копии через CLI:** `backup-create --directory ... --password-file ... --keep 7`, запись в 0600 через временный файл+rename, сохранение до N файлов, проверка режима 0600 файла пароля. В `arcvpn`-меню заменена потенциально опасная незашифрованная SQLite-копия, добавлен opt-in ежедневный timer.
5. **UI и локальная разработка:** экран 2FA, QR, журналов и статусов, `scripts/dev-local.sh`, `scripts/verify-stage3-local.sh`, `docs/ops/local-development.md`.

## Не реализовано и не подтверждено

- Изменение UFW из UI (с безопасным ownership правил и восстановлением SSH), TLS-renewal на реальном IP, публичная установка, фактический systemd helper, WireGuard/AmneziaWG сетевой трафик.
- Полный перенос _всей_ инфраструктуры (ноды, политики, история, IP-зависимые сертификаты): текущий шифрованный backup v2 переносит только VPN-профили и пользователей, администраторов и MFA не переносит намеренно.
- Обновления панели и VPN движков с безопасным rollback; автоматический update-agent отсутствует.
- Журналы теперь разнесены: файловая ротация панели имеет свой бюджет 500 МиБ по умолчанию, `journald@arcvpn` — независимые 200 МиБ по умолчанию с изменением через UI. Лимит journald применяется не к чужим службам; `--vacuum-size` не является точным жёстким лимитом для активных файлов. Требуются реальные испытания systemd.
- Нет единого глобального лимита на **все** журналы, БД и backup VPS: каждая подсистема имеет независимый бюджет.
- React production build, TypeScript typecheck, Playwright, VPS/systemd/HTTPS/SSH/firewall handshake **не запускались в этой среде**.

## Безопасность

- RFC 6238 TOTP использует SHA1 только как HMAC-OTP, а не для хеширования паролей. TOTP secret хранится в SQLite, защищённой правами учётной записи. Компрометация файлов БД позволяет извлечь секрет 2FA; нужна отдельная оценка рисков до production. Секрет не экспортируется в переносимый VPN-архив.
- Для логов привилегированный helper не принимает произвольные имена служб. Не изменять глобальный journald.conf, не выдавать root API web-процессу.
- Зашифрованные копии **не содержат** ключ шифрования; пароль задаётся отдельно, backup store должен быть вне VPS.
