# ArcVPN 0.4.2 — продолжение этапа 2, исходники

Дата: 2026-11-04. **Не production; внешний релиз не принят.**

## Что реально изменено

- Сборочный pipeline `scripts/build-amneziawg.sh` собирает три бинарника AmneziaWG 3.1 из **закреплённых upstream Git-тегов**: `amneziawg-tools v3.1.20260812`, `amneziawg-go v3.1.20260828`. Сборка выполняется на CI/build host, а не на VPS. Пакует corresponding upstream source archives и notice для лицензирования.
- `scripts/build-release.sh` требует собранный React, Go с CGO и все AWG binaries; публикует единый `dist/SHA256SUMS`. `install.sh` отвергает неполный release **до системных изменений**, проверяет контрольные суммы и размещает подписанный релизом набор AWG, не добавляя сторонних APT-репозиториев.
- AWG 3.1 по умолчанию: `HeaderProtectionKey`, `ContentPaddingAddition`, одинаковые `S1–S4=40`, `RandomTrailers=on`; `DisableCookies=off` для сохранения защиты WireGuard от перегрузки. Статические параметры сервера копируются в клиентский `.conf`. `I1–I5` не выдумываются и не включены.
- Root CLI больше не вызывает `awg-quick up`: он запускает **конкретно** `amneziawg-go` из релиза, валидирует конфигурацию, использует `awg-quick strip`, затем применяет `awg setconf` и фиксированные команды `ip`. Старый AWG kernel module не перехватывает создание интерфейса. При ошибке запуска выполняется ограниченный cleanup.
- Сохраняются запреты любых shell-hooks в пользовательских конфигурациях. CLI не наследует произвольные переменные окружения и не публикует секреты из вывода внешних команд.
- Обновлены тесты безопасного AWG 3.1 профиля, отрицательные проверки изменения параметров и тесты привилегированного запуска.

## Проверено локально

- `go test ./...` — PASS.
- `go vet ./...` — PASS.
- `go test -race ./internal/engines ./internal/protocols ./internal/app ./internal/httpapi ./internal/backup` — PASS (локально).
- `bash -n` для установщика и shell-скриптов — PASS.
- `scripts/build-amneziawg.sh` на Go 1.23.2 — ожидаемый отказ до скачивания чужих репозиториев: нужен Go >= 1.25.

## Не проверено и не должно называться работающим

1. **Фактическая upstream-сборка** AWG 3.1: текущая среда не имеет доступа к GitHub и Go >= 1.25. На Linux build-runner с Go 1.26 выполнить `scripts/build-release.sh`; проверить происхождение и лицензии собранных артефактов.
2. React production build и браузерная совместимость: отсутствуют `frontend/package-lock.json` и npm-зависимости; они должны быть созданы / установлены и проверены на машине с интернетом, а lockfile добавлен в исходники.
3. Реальные systemd, routing/NAT, HTTPS по IP, Hysteria2, Xray/XHTTP, WireGuard, AmneziaWG handshake/трафик: только внешний тестовый VPS и отдельный клиент.
4. Возможные изменения от upstream в CLI AWG 3.1 и используемых флагах: подтверждаются именно реальным бинарником, а не unit-моками.
5. Лимиты, геофайрвол, DNS/IPv6-утечки, поведение под нагрузкой и восстановление после перезапуска ядра требуют внешней приёмки.

## Следующее действие для Codex

Использовать `docs/testing/stage2-codex-handoff.md`. Сначала `npm install --package-lock-only` + `npm ci` и `scripts/build-release.sh` на Ubuntu 24.04 CI, затем в изолированной тестовой VM проверить развёртывание, исполняемые AWG бинарники и реальный трафик. При любой ошибке — устранить дефект и повторить тесты. Не устанавливать это на действующий 3x-ui.
