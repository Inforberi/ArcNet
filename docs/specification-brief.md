# Краткое задание для следующего ИИ-чата / Codex

**Статус:** проектирование. Нет реализации; не заявлять, что что-либо собрано или протестировано.

Сделать лёгкую **self-hosted VPN-панель**: Go + SQLite WAL + React/TypeScript/Vite + React Router Data Mode + TanStack Query + Tailwind + выборочные shadcn/ui, собственная дизайн-система и композиция компонентов; Xray-core как отдельный процесс, systemd по умолчанию, Podman опционально. Frontend статически собран, раздаётся Go; в production Node.js не нужен.

**Первый режим** — один VPS без отдельной ноды/агента, целевой стенд 1 vCPU/1 ГБ RAM включая ОС/Xray (не подтверждённый минимум). **При расширении** — управление удалёнными Go Agent+Xray из одной панели, установка VPS через SSH из UI, без отдельной веб-панели на нодах. География не важна; direct/каскад A→B/каскад B→A/резерв. Пользователи и подписки независимы от физического VPS.

**Основной UX:** компактная тёмная панель по характеру 3x-ui (не 1:1 копия), дашборд, пользователи, подключение, настройки. **Схема маршрутов и таблица нод** — переключаемые виды одного состояния. В обычном режиме панель сама устанавливает, выбирает совместимые параметры, генерирует ключи, открывает managed UFW-порты, проверяет Xray и публикует подписки. **Все технические настройки доступны через расширенный режим**, manual overrides нельзя молча перезаписывать.

**Безопасность:** SSH fingerprint из доверенного канала, временные SSH-секреты, разрешённые действия, no remote shell RPC, outgoing agent connection + individual mTLS identity, отдельный privileged helper, staged apply+rollback UFW/SSH/Xray, TLS по публичному IP/домену, 2FA сессий, аудит и encrypted backups. Отсутствие домена не делает VPN невидимым. Доставка подписок должна иметь резервные точки; автоматическое переключение мёртвого входа зависит от клиента. Исходящие каскады переключают новые соединения, не сохраняют существующие TCP-сессии.

Не начинать с универсального framework, биллинга или десятка протоколов.
