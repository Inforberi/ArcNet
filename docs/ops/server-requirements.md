# Требования к серверу и матрица совместимости

**Статус:** план тестирования. Ниже — **целевой профиль**, а не доказанные системные минимумы. Окончательная support matrix публикуется после интеграционных тестов на конкретных релизах ОС.

## A. Одиночный VPS: панель + VPN

| Параметр | Проектная цель / проверка |
|---|---|
| CPU | 1 vCPU: оценить реальную пропускную способность и задержку |
| RAM | 512 МиБ — новый контрольный профиль пользователя; весь VPN + ОС на этом бюджете ещё не проверен |
| Swap | Не обязателен, наличие/размер определяется после тестов; не считать заменой RAM |
| Диск | По итогам тестов: ОС + бинарники + база + логи + резерв; не обещать фиксированный минимум |
| ОС | Проверенные Ubuntu LTS / Debian Stable с systemd |
| Архитектура | Linux amd64 / arm64 после проверки бинарников и зависимостей |
| Доступ | SSH с правами на первоначальную установку, systemd, networking |
| Сеть | Публичный IPv4/IPv6 или задокументированный NAT/forwarding, доступ к нужным исходящим ресурсам |
| TLS | Проверяемый IP/домен сертификат или явно поддерживаемый закрытый контур |
| Порты | VPN-порт(ы); HTTPS-порт; SSH; ACME challenge порты согласно методу. Все проверяются на конфликты |

## B. Удалённая нода

| Параметр | Проектная цель / проверка |
|---|---|
| CPU/RAM | 1 vCPU / 512 МиБ — контрольный профиль, не гарантированный minimum/throughput |
| Управление | Исходящий аутентифицированный канал к панели, публичный agent API не нужен |
| ПО | Go Agent + Xray + systemd, без полноценной панели и отдельной БД |
| Firewall | Managed rules + облачный firewall провайдера учитывается отдельно |
| Фоновые задачи | Только bounded heartbeat/health/metrics и reconciler |

## C. Тесты ресурсоёмкости

Стандартный сценарий: 100 созданных пользователей, 10 активных VPN-клиентов, один активный администратор, профили direct и двухнодовый cascade в отдельных прогонах. Измерять RAM RSS/heap, ОС total memory и swap, CPU, FD, скорость сети, потерю пакетов, p95 API, SQLite write latency, disk growth. Сравнивать stand-alone и node режимы. Факт работы полного VPN в 512 МиБ не подтверждён, пока нет VM/VPS и traffic-замеров.

## D. Preflight/UX

Панель не должна жёстко отказывать только из-за того, что VPS не соответствует *рекомендованной* конфигурации. Для реально неподдерживаемой ОС/архитектуры/прав/безопасности выдавать блокирующую ошибку и объяснение. Предупреждать о нехватке диска, swap, стабильности DNS, свободных портах, provider firewall, root/sudo, часах и TLS. Поддержать dry-run.

## E. Политика развёртывания

- `systemd` по умолчанию — меньше слоёв сетевой и привилегированной настройки.
- `Podman` возможен как альтернативный packaging/deployment только после отдельных network/UFW/performance/security тестов.
- Docker/Podman не обязателен и не должен случайно изменить UFW для существующих сервисов.
- Сборка frontend — на CI/машине разработчика, не на целевом VPS.
