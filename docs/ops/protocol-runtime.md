# Автономный VPN: протоколы и границы исполнения (этап 2)

Дата: 2026-11-04. **Кодовый кандидат, без проверки на реальном VPS.**

## Движки и режимы

| Профиль | Исполнитель | Пользователи | Распространение | Что не доказано |
|---|---|---|---|---|
| VLESS + Reality TCP | Xray-core | UUID, существующие токены | URI + подписка | Совместимость конкретного клиента и внешняя доступность |
| VLESS + XHTTP + Reality | тот же Xray-core | UUID | URI + подписка | Поддержка текущего Xray и клиента, SNI/target |
| Hysteria2 | отдельный Hysteria | userpass, отдельные пароли | URI + подписка | QUIC в сети клиента, проверка IP TLS-сертификата |
| WireGuard | WireGuard + `wg-quick` | отдельные X25519 пары и IPv4 адреса | конфиг `.conf` + QR | доступность UDP, NAT/провайдерский firewall |
| AmneziaWG 3.1 | закреплённые `amneziawg-go`, `awg`, `awg-quick` (отдельный userspace) | отдельные X25519 пары и IPv4 адреса | конфиг `.conf` + QR | **релизная поставка реализована в коде, upstream binaries ещё не собраны и на VPS не испытаны**; версия клиента и handshake не проверены |

Все четыре дополнительных профиля опциональны; локальный VLESS работает без них. Это **не каскады** и не установка на удалённые ноды.

## Секреты, учётные данные и подписки

- Серверное хранилище: SQLite `protocols` + `protocol_credentials`; файлы конфигураций в `/var/lib/arcvpn`, права `0600`, каталог `0700`.
- В REST `GET /api/protocols` приватные ключи не сериализуются. Вкладка администратора `GET /api/users/{id}/connections` и скачивание `/api/users/{id}/connections/{kind}/export` раскрывают **индивидуальные** секреты только в авторизованной сессии.
- `GET /sub/{token}` публикует список URI VLESS TCP, XHTTP, Hysteria2. WireGuard/AmneziaWG не включены: единый формат подписок для них не универсален.
- Отключённый пользователь не попадает в конфигурации движков и не получает действующую публичную подписку. Раздельные ключи пользователя сохраняются при обычной деактивации.
- Зашифрованный backup **v2** содержит дополнительные профили, приватные ключи и секреты пользователей; архивы **v1** остаются читаемыми. Архив не включает пароль администратора, активные сессии и сертификаты данного VPS. При смене IP потребуются перевыпуск сертификатов и обновление URL.

## Система и привилегии

- `arcvpn-panel.service` непривилегирован. Только проверенный локальный сокет передаёт ограниченный список операций systemd root-helper (`restart/stop` конкретного VPN-движка); произвольный shell/exec из HTTP API отсутствует.
- КОНТРОЛЬНАЯ ГРАНИЦА: **никогда не вызывать `wg-quick`/`awg-quick` с файлом, доступным на запись пользователю `arcvpn`**. Отдельная root CLI `arcvpn-core tunnel up|down wireguard|amneziawg` проверяет whitelist допустимых полей, переносит конфиг в root-owned `/run/arcvpn`, и только после этого вызывает `wg-quick`.
- `PostUp/PreDown/PreUp/PostDown` и другие shell-директивы конфигураций запрещены. Фиксированный `arcvpn-tunnel-net` (root-owned systemd ExecStartPost/ExecStopPost) добавляет/удаляет только три NAT/FORWARD правила для интерфейсов `arcwg`/`arcawg` и диапазонов 10.76/16, 10.77/16.
- IPv4 forwarding выставляется через `/etc/sysctl.d/90-arcvpn-forward.conf`. IPv6 **не туннелируется**: клиент получает `AllowedIPs=0.0.0.0/0`, не `::/0`. Это не гарантия отсутствия IPv6-утечек при наличии IPv6 у клиента; политику IPv6/kill-switch следует отдельно проверить и реализовать.
- Изменение UFW/внешнего облачного firewall при создании VPN-профиля **ещё не автоматизировано** (этап 3); на тестовом VPS порты необходимо контролируемо открыть с проверкой сохранения SSH.
- `GET /api/protocols/health` отражает **только локальное состояние systemd**. Это не проверка VPN из сети пользователя и не измерение ping клиента.

## Поддержка AmneziaWG

Официальные источники: https://docs.amnezia.org/documentation/amnezia-wg/ , https://docs.amnezia.org/documentation/instructions/install-amneziawg-go/ , https://github.com/amnezia-vpn/amneziawg-tools .

**Схема 0.4.2:** upstream-теги `amneziawg-go v3.1.20260828` и `amneziawg-tools v3.1.20260812` собираются на Linux build-runner через `scripts/build-amneziawg.sh`. В релиз включаются `amneziawg-go`, `awg`, `awg-quick`, исходники upstream, SHA256SUMS и notice о лицензировании. Installer копирует проверенные готовые binaries без сторонних PPA и без Go/npm на VPS. Root tunnel CLI запускает userspace `amneziawg-go` напрямую (не полагается на установленный модуль ядра), затем фиксированными командами `awg`/`ip` применяет конфигурацию. Привилегированный процесс не обрабатывает произвольные shell-хуки.

В AWG3.1 `HeaderProtectionKey` требует S1–S4 >= 12; выставлены одинаковые S=40 и `RandomTrailers=on`. `DisableCookies=off` сохраняет WireGuard cookie reply — отказ от этой защиты небезопасен по умолчанию. Параметры `I1–I5` не устанавливаются без проверенного профиля. Совместимость разных клиентов и actual AWG3 handshake остаются внешними испытаниями. На 2026-11-04 сборка downstream AWG в данном контейнере заблокирована Go 1.23 и отсутствием сети. Не подменять AWG обычным WG и не объявлять профиль работающим при отсутствии движка.

## Применение конфигураций и возврат состояния (0.4.1)

До изменения файлов engine manager генерирует и проверяет **все** необходимые конфигурации и спрашивает состояние конкретных перечисленных systemd-служб через root-helper (операции `status hysteria|wireguard|amneziawg`). Если любой валидатор или запрос состояния не прошёл, активные файлы/службы не изменяются. Для успешной подготовки новые файлы заменяются атомарно; устаревшие удаляются только после остановки соответствующей службы. При ошибке выполняется best-effort восстановление снимков конфигураций и прежних активных/неактивных состояний. Неуспешное восстановление возвращается как ошибка, а не объявляется успехом. Это не гарантирует отсутствие прерывания текущих соединений при рестарте или при сбое ядра/daemon.


## 0.4.3: настройка AWG3.1 до проверки upstream

- Значение по умолчанию: `RandomTrailers=off`, `ContentPaddingAddition=32-128`, `DisableCookies=off`. Не утверждаем, что это оптимальная защита от DPI — это консервативное решение в пользу стабильности.
- Основание для проверки: https://github.com/amnezia-vpn/amneziawg-go/issues/185 и https://github.com/amnezia-vpn/amneziawg-go/issues/186. Это сообщения об ошибках, а не доказательство компрометации криптографии.
- Codex должен проверить поддержку значений `off`, провести handshakes и передачу пакетов, включая MTU/UDP и сверку client/server параметров. При необходимости менять defaults только с регрессионными тестами и записью ADR.
## Локальный учёт Hysteria2 — 2026-11-05

При apply автоматически добавляется private trafficStats на `127.0.0.1:19823`; публично этот TCP-порт не открывается. Его нельзя занимать панелью/XHTTP. Runtime directory/config/`hysteria-stats.key` private, key не переносится backup. Collector требует Linux procfs и systemd 248+ для точной epoch; при недоступности данных UI показывает unknown, конечный общий пакет закрывается по политике freshness. Default unlimited сохраняет прежний доступ. WG/AWG/remote accounting остаются отдельными интеграциями. Отзыв/квота/срок меняют allowlist с restart Hysteria; другие клиенты процесса могут переподключаться. Неудачное применение — pending, не доказанный disconnect.
