# Локальные start / stop / restart / status

Контракт A1, 2026-11-06. Реализован в исходниках; Linux fixtures/tests/build прошли. **Настоящий systemd/VPS/handshake ещё не проверены.** Нужны соответствующие новый core, wrapper, units, cert hook и tmpfiles config; один старый установленный wrapper или core-only update не обеспечивают этот контракт.

Команды относятся к стандартным путям/именам установки `install.sh`. Произвольные custom serve paths/unit names и отдельные managed-node установки не обнаруживаются и не управляются этим CLI.

Wrapper сначала проверяет `lifecycle-v1` через безопасный core help, до передачи root-команды. Несовместимый старый core отклоняется, чтобы неизвестная команда не открыла SQLite от root. Проверка не заменяет совместимость unit-файлов и миграцию пакета.

```bash
sudo arcvpn
sudo arcvpn start
sudo arcvpn stop
sudo arcvpn restart
sudo arcvpn status
sudo arcvpn status --json
sudo arcvpn restart panel
sudo arcvpn restart xray
sudo arcvpn restart hysteria
sudo arcvpn restart wireguard
sudo arcvpn logs
sudo arcvpn logs panel
sudo arcvpn logs hysteria
sudo arcvpn logs wireguard
```

## Область и семантика

Общие команды управляют локальными panel/Xray/Hysteria/WireGuard и control socket/helper. Старый установленный AmneziaWG учитывается только для совместимости; новые профили/протоколы не добавляются. Удалённые ноды, SSH, UFW, чужие службы, сертификатные и backup timers не меняются.

`stop` сохраняет данные и конфигурации. Сначала устанавливается root marker, затем останавливается панель с ожиданием завершения, снимаются доступные counters, останавливается socket/helper и локальные движки. Если панель не остановилась или её состояние неизвестно, переход к отключению движков запрещён. Отказ одного из остальных stop не скрывает состояние других; общий результат частичный, exit1.

`start` запускает socket, убирает marker и через процесс пользователя arcvpn выполняет тот же reconcile конфигураций, что worker панели. Только после успешного apply запускается панель. Не включаются выключенные профили, не создаются новые credentials. Отсутствующий необязательный unit допускается при stop/status отключённого компонента; отсутствие нужного компонента при apply/start даёт ошибку. Повторные start/stop при уже достигнутом состоянии не перезапускают службы.

`restart` проходит контролируемый stop/start. Варианты `restart panel|xray|hysteria|wireguard` кратко останавливают панель для сериализации и применяют сохранённую политику; затем перезапускают выбранный компонент. Остальные движки не останавливаются этим вариантом, но reconcile может исправить их уже существующее несоответствие desired state. Отключённый выбранный профиль не запускается. После глобального stop частичный restart отклоняется: нужен общий start.

Если apply/start не удался, выполняется bounded cleanup с возвратом root marker; сохраняются конфиги/ключи. Если cleanup тоже не удался, выводятся фактические оставшиеся active/unknown компоненты, а не утверждение «всё остановлено». Для восстановления используйте status/logs/doctor, исправление причины и новый start; не удаляйте marker как обход проверки.

Timeout/обычная отмена завершают выделенную группу дочерних процессов, включая runuser/core; cleanup имеет отдельный ограниченный контекст. Это не гарантия восстановления после SIGKILL/сбоя ОС: такой сценарий и фактические systemd jobs требуют отдельной VM-проверки. Базовый doctor сохранён; полный установочный preflight относится к A2/A3.

## Учёт и статус

Финальное наблюдение — best effort, без сброса upstream counters. Неподтверждённый хвост отражается предупреждением. Смена process/interface epoch может оставлять `incomplete`/`needs_review`; существующие review gates и расход не очищаются для успешного запуска. **Бесшовное продолжение конечного пакета после любого рестарта не заявлено:** проверяйте состояние пакетов, фактический отзыв и задержку на VPS. Alive/active/успешный reconcile не доказывают handshake, полный расход или разрешение трафика конкретному пользователю.

Status выводит desired/actual/error по компонентам. Helper может быть `on-demand` и не обязан постоянно оставаться active. Неизвестные/masked/systemd ошибки не превращаются в inactive. JSON не содержит ключей, токенов, credentials или сырого вывода systemctl.

- Exit0: запрошенное состояние подтверждено; предупреждение о counters возможно отдельно.
- Exit1: ошибка, неизвестное состояние или частичное выполнение. При недоступной БД stop всё равно пытается отключить известные local units, но status сообщает недоступность конфигурации.
- Exit2: неверные аргументы/компонент, без системных действий.
- Exit3: другой lifecycle/update держит общий lock, без изменений.

Журналы — последние80 записей выбранных ArcVPN units из namespace, bounded32KiB. Это административный локальный вывод, не публичный диагностический архив.

## Marker, reboot и обновления

`/run/arcvpn-lifecycle/lock` — root-owned, no-follow regular file, flock nonblocking; path не удаляется при завершении unit. Файл `paused` доступен контроллеру только на чтение. Worker apply и helper restart учитывают marker; units имеют отрицательный ConditionPathExists. Сертификатный hook продолжает устанавливать обновлённые файлы, но не пробуждает остановленную панель. Updater использует тот же lock и отказывается работать при paused; прежний отдельный `/run/arcvpn-update/lock` сохранён.

Marker действует **до перезагрузки**: `/run` очищается, после boot работает существующая политика systemd enable/disable. `stop` не меняет автозапуск. Tmpfiles создаёт защищённый каталог заново; ни таймеры renewal/backup, ни данные не удаляются. Сохранение stopped между reboot и отдельный UI автозапуска этим блоком не реализованы.

На существующей установке требуется проверенная миграция units/hook/tmpfiles/wrapper в релизе A2; повторный install поверх рабочей панели не является этой миграцией. Общий lock предотвращает наложение CLI и updater; полноценная VM-проверка updater/reconcile/частичных отказов по-прежнему обязательна. Изменение политик SSH/сетевого firewall не входит в A1.
