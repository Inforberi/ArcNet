# Выпуск обновления одной командой

Только доверенный компьютер сопровождающего. На VPS и в панель приватный ключ не передаётся. Новая логика пока в исходниках; A10/0.7.1 не подписаны и не опубликованы из этого рабочего блока.

## Подготовка один раз

Нужны Git, Go, Docker/buildx, Python3, tar и авторизованный GitHub CLI `gh`. Python3 нужен только для build receipt/manifest; на VPS не требуется. Репозиторий — чистая ветка `main`, актуальная с origin, версия в `VERSION`, описание в `docs/releases/ВЕРСИЯ.md`. Скрипт не устанавливает инструменты и не меняет настройки машины.

Используйте **существующий** приватный ключ с правами0600, соответствующий `deploy/update-public.hex`. Его публичный SHA256: `5f80f78a69441940b93bece69ce027f4ffe4f26452f5bed96da8bb520b4cd69a`. Другой ключ будет отклонён до сборки. Не генерируйте новый ключ для обхода ошибки. На текущем компьютере правильного ключа нет; он находится на другой машине владельца.

## Переход старых панелей: один раз

На компьютере с правильным ключом после получения этого коммита:

```bash
git pull --ff-only
ARCVPN_SIGNING_KEY=/путь/к/существующему/installer-private.hex ./scripts/release-update.sh --bridge --publish
```

Это выпускает A10 через прежний v1 catalog, минимум A7. После его установки панель и root helper понимают SemVer/v2. У A5/A6 требуется прежний первоначальный переход из [install-and-update](install-and-update.md), обычный UI update там не считается рабочим. Backup/snapshot перед обновлением обязателен.

Затем обычный выпуск 0.7.1:

```bash
ARCVPN_SIGNING_KEY=/путь/к/существующему/installer-private.hex ./scripts/release-update.sh --publish
```

Без `--publish` команда только соберёт, подпишет и проверит пакет локально. Путь к ключу можно передать через `--key`. Не помещайте содержимое ключа в переменную, команду или GitHub Secrets.

## Следующие версии

Обновите `VERSION`, создайте `docs/releases/ВЕРСИЯ.md` (до2000 UTF-8 байт) с изменениями, исправлениями, известными ограничениями и совместимостью. Выполните относящиеся к изменению проверки, обновите SOURCE_MANIFEST, закоммитьте и отправьте исходники. Запустите ту же команду. По умолчанию minimum=A10; при изменении совместимости явно укажите `--minimum-version ID`. Это утверждение издателя должно быть подтверждено, подпись сама не доказывает совместимость.

Скрипт: проверяет clean snapshot/ключ/отсутствие тега → собирает pinned Linux/amd64 core с React и release checks → выполняет `frontend-check`/`version` → связывает проверенный binary SHA256 с BUILDINFO → подписывает ZIP и каталог → повторно выполняет VerifyPublished → создаёт tag/draft → загружает asset и сравнивает скачанные байты → публикует release → коммитит и отправляет подписанный каталог. Ключ остаётся вне Docker. BUILDINFO — receipt доверенного builder, не внешняя аттестация.

Нормальный ID: `0.7.1`, `0.8.0`, prerelease `0.8.0-rc.1`. Прежние `stage5-aN` не переименовываются. Build metadata хранится отдельно; `+build` в публикуемом ID запрещён. ZIP — `update-0.7.1.zip`, bridge — `update-a10.zip`. Обновление core/UI не выпускает автоматически installer/bootstrap и не меняет службы/hooks ОС.

## Если выпуск прервался

Не перезаписывайте asset, не удаляйте tag и не запускайте force push. Скрипт намеренно откажется повторно использовать output/tag/ID. Каталог публикуется последним, поэтому незавершённый draft сам не разрешит установку.

Проверьте `git status`, `git log -1`, `gh release view vВЕРСИЯ --repo Inforberi/ArcNet` и `dist/release-ВЕРСИЯ`. Если draft не завершён — сравните его asset с локальным подписанным ZIP перед ручным завершением. Если release опубликован, но каталог не отправлен — используйте уже созданные `update-catalog*.json` и `catalog-source.json`, не пересоздавайте пакет. Если catalog commit уже создан, но push прервался — отправьте именно этот commit. Конфликт с чужими изменениями разбирается явно, без reset/stash/force.

Если в v2-source пока нет bridge, это допустимо: bridge обнаруживается по v1, normal release требует установленный A10. Старые строки v2-source — только реальные ранее опубликованные записи. История GitHub информационная; источником разрешения установки остаётся подписанный каталог.

## Приёмка

Проверки упаковки/подписи и локальный UI не заменяют systemd/VPS apply. Владелец проверяет backup, обновление через панель, фактическую версию после restart, сохранение доступа/VPN, диагностику отказа. Произвольный возврат на старую версию блокируется: безопасный откат данных пока не реализован.
