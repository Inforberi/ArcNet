# Доверенные обновления ArcVPN

## Граница доверия

Updater никогда не принимает произвольный `.zip` с бинарником. Обязателен архив с `manifest.json` и подписью `manifest.sig` Ed25519. Подписываются версия и SHA-256 всех файлов. Публичный ключ владельца релиза заранее помещают в `/etc/arcvpn/update-public.hex` из доверенного release-канала; приватный ключ генерируется и хранится **только offline**, не размещается на VPS, в панели или в репозитории.

Однократное создание пары ключей на доверенной машине:

```bash
./dist/arcvpn-linux-amd64 update-keygen --out-dir "$HOME/arcvpn-signing-keys"
```

На доверенной release-машине после сборки приложения (флагами можно передать все компоненты):

```bash
./dist/arcvpn-linux-amd64 update-sign \
  --binary dist/arcvpn-linux-amd64 \
  --version 0.5.1 \
  --private-key "$HOME/arcvpn-signing-keys/update-private.hex" \
  --output arcvpn-signed-0.5.1.zip
```

Для полного обновления передаются также `--xray`, `--hysteria`, `--awg`, `--awg-quick`, `--amneziawg-go` с путями к фактическим совместимым бинарникам. Нельзя обновлять лишь часть тройки AWG. Файлы внутри signed-архива проверяются до замены; после применения панель и затронутые активные службы перезапускаются, при ошибке запуска бинарники откатываются. Обновление может временно прервать VPN-соединения, а успешный `systemctl is-active` **не гарантирует** сохранение пользовательского трафика.

В интерфейсе: **Безопасность → Обновление ArcVPN → Загрузить/проверить → Установить**. Предусмотрена отмена подготовленного обновления. Без установленного доверенного ключа интерфейс не позволит провести обновление.

## Ограничения

- Инструмент не реализует автоматическое скачивание release из интернета: только операторский подписанный пакет.
- `systemd` и реальный rollback необходимо проверить на VPS. Ни Go-тест, ни подпись Ed25519 не заменяют проверку загрузки совместимого Xray/WG/QUIC.
- Обновления схемы данных требуют отдельной стратегии совместимых миграций: откат только бинарника может быть недостаточным при необратимой миграции. **Не устанавливать обновления с несовместимыми DB migration** до реализации миграционного протокола.
- Старые архивы нельзя автоматически считать безопасными; нельзя включать неаутентифицированный autoupdate.
