# Бюджет ресурсов и методика замеров

## Цель, а не обещание

**Один VPS: 1 vCPU / 1 ГБ RAM**, включая Linux, Go-панель, SQLite и Xray. Цель относится к небольшому частному использованию, не к высокой скорости/сотням одновременных соединений. Поддержку надо подтвердить испытаниями на реальном VPS и воспроизводимом профиле нагрузки.

В пользовательском скриншоте работающей 3x-ui показаны около **118 МБ памяти панели** и **293 МБ / 733 МБ памяти всей машины** в один момент. Это снимок состояния чужой реализации, **не benchmark нашей будущей системы** и не доказательство её вместимости в 1 ГБ.

## Проектные бюджеты для первой оценки

| Участок | Начальная цель | Комментарий |
|---|---|---|
| Go API + HTML/assets + SQLite | до 150 МБ RSS в простое | будет проверено на реальной сборке |
| Go Agent на отдельном VPS | до 40 МБ RSS в простое | отдельная цель, без Xray |
| UI-сервер | 0 дополнительных процессов | Vite-сборка раздаётся Go |
| Node.js / Redis / PostgreSQL / брокер | 0 обязательных production-процессов | если появятся — отдельный ADR |
| Весь VPS | менее 1 ГБ фактического использования с запасом | Linux page cache, Xray и spike нагрузку учитывать отдельно |

Нельзя суммировать только RSS и делать вывод о фактическом потреблении всей ОС. Использовать `free`, cgroup metrics, `/proc`, `ps`, временные ряды, pprof и сравнение до/после. Применение сертификатов/SSH/updates может временно повышать CPU/RAM.

## Функциональная нагрузка

- 100 пользователей в базе, 10 одновременно активных клиентов, 1 администратор в браузере.
- 1–2 Inbound, затем расширение до 5 нод; измерять отдельно каждый режим.
- Сценарии: простое, обычный трафик, burst подключений, частые изменения пользователей, открытая вкладка с графиками, закрытая вкладка, потеря удалённой ноды, большой список клиентов.
- Фиксировать p50/p95/p99 латентность API, writes SQLite, CPU% одного vCPU, RSS/PSS процессов, socket counts, disk growth, полученные ошибки и retry.

## Рекомендации к реализации

Ограниченные очереди и concurrency, reuse соединений, компактный JSON/API с пагинацией, агрегация метрик, SSE с консервативной частотой и backoff, ленивые страницы и чанки, отсутствие необоснованных polling-запросов, корректный cleanup goroutine/listeners/events. Измерять прежде чем переписывать.
