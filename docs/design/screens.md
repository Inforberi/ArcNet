# Экранные референсы: что сохраняем и улучшаем

**Источник визуального референса — четыре скриншота 3x-ui, предоставленные пользователем 2026-11-03.** На них видна конкретная конфигурация, а не исчерпывающий список возможностей программы.

## [Дашборд](../references/screenshots/dashboard.png)

**Нравится/сохраняем:** тёмный спокойный фон, тонкие границы, синий акцент; компактный верхний статус Xray и версии панели; быстрые системные действия; карточки CPU/RAM/Swap/Disk с крупными значениями и sparklines; широкий график сетевого трафика и график TCP/UDP сокетов; блок uptime/процессов/IP.

**Улучшаем:** сводка здоровья нескольких VPS и каскадов, отдельный статус subscription-service, предупреждения о рисках (диск, cert renewal, отказ egress), фильтр периода, меньше второстепенного шума. Не сводить статус к одной зелёной точке. Не показывать рекламные блоки на рабочем дашборде.

## [Список пользователей](../references/screenshots/clients.png)

**Нравится/сохраняем:** верхняя сводка Clients / Online / Exhausted / Near Limit / Disabled / Active; кнопки добавить/групповые действия; поиск/фильтр/сортировка; плотная таблица: действия, включено, online, клиент, группа, inbounds, трафик, скорость, остаток, длительность; цветовая семантика; быстрые операции QR, информация, reset, edit, delete.

**Улучшаем:** не полагаться только на цвета (текст + иконка), пояснения IP/HWID, гибкие/скрываемые колонки, tooltip и доступные имена кнопок; массовые операции с подтверждением, отдельные credentials на устройства, global quota. В компактных размерах таблица скроллится или использует адаптивное карточное представление.

## [Список подключений](../references/screenshots/inbounds.png)

**Нравится/сохраняем:** сверху отправлено/получено, суммарный трафик, число подключений; создание/общие действия; компактный список с ID, on/off, названием, портом, протоколом, количеством клиентов, трафиком/скоростью, сроком.

**Улучшаем:** добавить видимую принадлежность к серверу, если нод несколько; показывать firewall status и ошибку bind/proxy; не смешивать «подключение VPN» с «маршрутом/каскадом»; при создании автоматически готовить соответствующее правило firewall.

## [Форма редактирования клиента](../references/screenshots/client-form.png)

**Нравится/сохраняем:** модальное окно с заголовком, вкладками Основные/Учётные данные/Ссылки; двухколоночная сетка; лимит GB/IP/HWID, срок и first use, reset, auto-renewal, комментарий, группа, привязанные входящие; фиксированная нижняя панель с отменой/сохранением; цветная опасная операция reset traffic.

**Улучшаем:** длинные формы делить на смысловые секции; в «Основные» оставлять пользовательскую политику, а Reverse Tag/host-rule override переносить в «Дополнительно»; русские названия вместо смешения `Auto renewal`, `Reverse tag`; видеть последствия сохранения (какие ноды затронуты), не терять несохранённое; ошибки показывать рядом с полем и общей причиной. Не показывать `0` без разъяснения «без ограничений».

## Визуальные ограничения и референсы

- Сохраняем **характер** интерфейса: профессиональный тёмный, насыщенный данными, без огромных декоративных блоков.
- Не копируем механически все пиксели или исходный CSS/иконки 3x-ui; собственные токены и визуальные компоненты, лицензионная проверка для прямого заимствования.
- В UI важна одинаковая ширина контролов, предсказуемые фокусы, выравнивание и неподвижные иконки при раскрытии групп.
- Учитываем пользовательскую цель: минимум ручных настроек, понятные вкладки, быстрый доступ к расширенным параметрам.

## Порядок создания макетов

1. Layout + navigation + table primitives.
2. Clients (список + форма).
3. Dashboard.
4. Inbounds.
5. Servers + SSH wizard.
6. Routes/failover.

Каждый экран — состояния: loading, empty, error, offline, partial-data, success, permission-denied, long-running operation.

## [Схема и таблица нод](topology-and-table.md)

**Новый референс пользователя:** на экране одновременно важны реальные связи нод и их техническое состояние. Фиксируем **два представления** — «Схема» и «Таблица» — без дублирования данных, со стабильным выделением выбранного сервера и маршрута. Простой режим показывает роль, маршрут и статус; расширенный — Inbound/Outbound/port/transport/health/revision. География не определяет направление каскада. См. полную [спецификацию](topology-and-table.md).
