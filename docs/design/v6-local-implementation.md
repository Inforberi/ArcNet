# Перенос v6 — первый локальный блок, 8 ноября 2026

Это начало переноса в **рабочий frontend**, не полная реализация функций демо. Backend пользователей, credentials, VPN и подписок не менялся. Релиза, push и установки на VPS нет.

## Изменения

- `frontend/src/shared/design-system/tokens.css` — семантические темы, цветовые роли, обводки, selected/focus, графики, fluid spacing/type на диапазоне375–1920. Default dark v6; дополнительная тема переопределяет роли, а не компоненты.
- `components.css` — общая реализация nav/buttons/fields/panels/dialogs/tables/status/charts и адаптивного поведения. Старые literal colors общего style.css заменены ссылками на роли; старые light-selector overrides удалены. Полная очистка feature-specific inline/utility colors — дальнейший этап.
- Видимый пункт «Версии ArcNet» и отдельный route, использующий существующий UpdateSettings. Старый переход через настройки сохранён для совместимости.
- «Подключения» в навигации и заголовке. У пользователей сводка только по существующим данным (нет вымышленного online), карточное представление таблицы на мобильном экране.
- Общий dialog сохраняет прежнюю защиту черновика, focus, Escape/backdrop и безопасные mutation API. Сетевые/engine операции не добавлялись.

### Системные причины и приоритет

1. **P1 — дизайн-система ещё не единственный владелец геометрии.** `style.css` и `shared/design-system/components.css` задают повторные правила для controls, таблиц и breakpoint. Общий Button не задаёт inline-flex для иконки/подписи; screenshot показывает перенос иконки. Решение: один канонический стиль каждого primitive, composition вместо повторных feature overrides. Не делать глобальный CSS reset с потерей поведения существующих форм.
2. **P1 — адаптив таблиц меняет структуру слишком рано.** Container1050 переводит все восемь колонок Users в двухколоночную карточку; screenshot4 показывает длинный пустой блок. Нужно три содержательных режима: таблица, компактная строка с второстепенными деталями, мобильная карточка. Набор полей карточки отдельный, без дублирования runtime/selection handlers. Длинные имена/адреса и 200% zoom входят в приёмку.
3. **P1 — навигация карточки пользователя дублирует сценарии.** Обзор повторяет поля редактора, отдельный device dialog меняет оболочку того же окна. Направление: одна стабильная оболочка, «Параметры»/«Активность», отдельное действие выдачи доступа. Выданные credentials не называть физическими устройствами; не изображать отсутствующее IP enforcement рабочим.
4. **P1 — раскрытие локальной секции меняет глобальный режим.** `Advanced` вызывает `setMode`, что раскрывает/сворачивает другие секции через context и сохраняет это между страницами. Локальные раскрытия должны оставаться локальными; глобальный режим меняется только явно. Обязательное невалидное поле раскрывается независимо от режима.
5. **P1 — разрушительные действия оформлены неодинаково.** `window.confirm/prompt` в backup/users/settings/nodes/routes/update, отдельный guarded Dialog и inline diff. Нужен общий confirmation pattern с объектом/последствиями, кнопкой конкретного действия и безопасной отменой. Не удалять подтверждения, version checks, блокировки busy и защиту dirty forms.
6. **P2 — подсказки и ошибки не являются полноценным контрактом Field.** Description рисуется как small, но не связана с input через aria-describedby; единого error/id/aria-invalid API нет. Многие формы показывают только общую ошибку. Сделать общий form-control contract и summary при нескольких ошибках; select/textarea/checkbox/switch используют его же правила.
7. **P2 — не определены варианты состояния и размеров.** Checkbox применяется и для selection, и для access, и для выбора пакета, часто в большой карточке. Нужны согласованные compact/regular/touch sizes, selection vs toggle semantics, единый hover/focus/selected/loading/disabled/error. Disabled действие объясняется, а не просто сереет. Touch target не равен размеру маленькой иконки.
8. **P2 — информационные сообщения конкурируют с действиями.** Повторные неизвестные показатели, длинные технические оговорки и одинаковый Notice для разных смыслов. Один краткий статус на блок; причина и действие рядом; подробная диагностика раскрывается. Существенные ограничения безопасности остаются видимыми до подтверждения операции.

### Правила системы и критерии приёмки

- Сохраняем тёмный v7 и фиолетовый accent. Единые spacing roles: control gap, label gap, section gap, panel/dialog padding; базовая шкала4/8/12/16/24/32, без назначения одного большого padding всем элементам.
- Button с неразрывной парой icon/text; toolbar содержит первичное и вторичные действия, которые перестраиваются целыми кнопками. Формы не масштабируются вместе с шириной всего экрана.
- Common FormControl, Select, Checkbox, Switch, Tabs/segmented, Disclosure, Dialog shell, confirmation, Toolbar, DataList, Status/Empty/Error и QR composition. Сначала существующие компоненты/установленные зависимости. Дополнительный primitive — только для конкретного непокрытого поведения, после документации; не библиотека ради нового стиля.
- `clamp` применяется к ограниченным spacing/width roles, не заменяет структурные breakpoint. Проверять320/375/768/1024/1440/1920 и промежуточные ширины, высоту viewport, 200% zoom и клавиатуру телефона. Это целевые проверки, пока NOT RUN.
- Диалоги: устойчивый header/body/footer; один scroll body, безопасное закрытие/Escape/focus, доступный primary action, safe-area и reduced motion. Не создавать новый dialog при обычном переключении раздела того же объекта.
- Визуальная приёмка полного сценария: добавить пользователя → настроить пакет/профили → выдать QR/файл → изменить → увидеть результат/ошибку. Затем тот же pattern распространяется на остальные экраны; общий style не считается законченным до проверки зависимых экранов.

Аудит не менял runtime/UI-код и не запускал build/tests: для текстового анализа они не подтверждают рендер. Следующее изменение начинается с общих primitives/поведения Advanced и адаптива DataList, затем user/editor/QR, затем остальные перечисленные поверхности. Не добавлять функциональность, которую backend пока не исполняет, как будто это рабочие настройки.
