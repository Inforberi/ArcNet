# ArcVPN 0.7.0 — редактор черновиков маршрутов

Дата: 2026-11-05. Продолжение [stage5 foundation](release-0.7.0-stage5-foundation.md) по решению пользователя: исправить целостность маршрутов/backup, добавить управление стрелками и проверить frontend. Набор протоколов не расширен, этап 6 не начат.

## Реализовано

- React Flow 12.12.1: основной и резервный путь соединением точек карточек, перемещение карточек, масштабирование, выбор сервера и назначение роли кнопками. Удаление основной стрелки переводит черновик в direct и очищает резервы. Удаление резервной убирает только этот резерв. Все связи явно помечены как черновики.
- Схема, форма и таблица используют одну модель `RoutePolicy`. На мобильном по умолчанию таблица; все действия доступны без перетаскивания. Полный список нод доступен в форме, схема ограничивает количество дополнительных карточек и предлагает поиск для большого реестра.
- Единые переходы формы очищают несовместимые выходы, ограничивают четыре резерва; порядок резервов меняется кнопками. Сброс формы очищает весь черновик. Проверка циклов учитывает основные и резервные рёбра остальных политик; окончательная проверка остаётся на сервере.
- Preview показывает значения до/после, а не только названия полей. Изменение любого поля делает старый preview недействительным; поздний ответ preview не подтверждает изменённый черновик. CAS-конфликт сохраняет пользовательский ввод и предлагает явно загрузить серверную версию.
- Удаление/отзыв ноды и начало SSH purge/detach запрещены, пока нода используется входом, основным или резервным выходом. HTTP 409 перечисляет названия зависимых черновиков. Проверка и изменение находятся в одной SQLite-транзакции. После начала удаления новые ссылки на ноду запрещены.
- Encrypted backup v4 включает черновики маршрутов, проверяет граф, метаданные и наличие всех нод. Ноды и маршруты экспортируются согласованно и восстанавливаются в одной транзакции. Восстановление увеличивает версии маршрутов, чтобы старая форма не перезаписала восстановленные данные. Ошибка применения движков восстанавливает предыдущие черновики; мутации маршрутов разделяют application lock с восстановлением.
- Форматы v1/v2/v3 читаются. Они не заменяют текущие маршруты; несовместимый v3 с отсутствующими нодами отклоняется целиком. v4 заменяет маршруты, включая явно пустой список. В UI preview указаны количество маршрутов и поведение версии.
- Реальный npm lockfile. Несуществующая react-query 5.90.0 заменена опубликованной 5.90.1; Router 7.18.5 и Vite 7.3.7 закрывают advisories, выявленные npm audit. React Flow загружается отдельным lazy chunk, без включения в начальную загрузку остальных страниц. Это не нагрузочный benchmark.

## Контракты и ограничения

Новых apply/activate/publish endpoints нет. Черновики не генерируют межнодовые credentials, не изменяют Xray, firewall, SNI, geo-базы или подписки. Проверка циклов по VPS по-прежнему запрещает одновременные A→B и B→A; разрешение независимых каналов требует отдельной доменной модели. Параллельная балансировка не реализована и не подменяется резервированием.

v4 не является полной копией инфраструктуры: переносит только ранее поддерживаемое VPN-состояние, identities нод, лимит логов и новые route drafts. Runtime receipts, SSH-секреты, enrollment tokens, браузерные сессии и подтверждения VPN не импортируются. Восстановление архива без настроенного локального VPN по-прежнему не поддерживается. После переноса ноды требуют отдельной проверки/настройки; маршруты остаются черновиками.

Фактические проверки и среда: [протокол](testing/local-results/stage5-2026-11-05-routing-ui.md). Полная приёмка этапов 4–5 остаётся внешней.
