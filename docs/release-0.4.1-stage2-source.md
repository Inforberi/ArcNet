# ArcVPN 0.4.1 — этап 2, кодовый кандидат

Дата: 2026-11-04. **Это только исходники; production-бинарника нет. На рабочий VPS не устанавливать.**

## Что реализовано в коде

- Независимые профили и ключи VLESS Reality TCP, XHTTP Reality, Hysteria2, WireGuard и AmneziaWG 3.1.
- Генерация конфигураций Xray, Hysteria, WireGuard/AWG, отдельных клиентских URI/`.conf`, QR и подписки для поддерживаемых прокси-клиентов.
- Добавление, отключение и удаление профилей из REST API и React UI, отдельная серверная диагностика состояния служб.
- Зашифрованное резервное копирование ArcVPN v2 с ключами дополнительных протоколов; сохранена совместимость с прежним v1.
- Строгая фильтрация wg-quick/awg-quick директив перед исполнением под root; пользовательские shell-хуки запрещены.
- **Исправлено в 0.4.1:** в ходе восстановления удаляемые службы больше не останавливаются до валидации всех новых конфигураций. При неудачном запуске восстанавливаются старые файлы и состояния служб (best effort, ошибки отката не скрываются).
- **Исправлено в 0.4.1:** системный helper позволяет читать состояние только строго перечисленных systemd-служб. Ошибки связи с systemd не приравниваются к неактивной службе.
- **Исправлено в 0.4.1:** отключённому пользователю API не предлагает VLESS-ссылку; выдача конфигураций/подписок запрещает кеширование.

## Что не реализовано / что не проверено

- **Отсутствует автоматическая установка AmneziaWG 3.1 в `install.sh`.** Настройка AWG из UI закономерно должна отказать, если `awg-quick`/совместимый движок отсутствуют. Требуется совместимая безопасная цепочка поставки и проверка на реальном Linux.
- Не проверено реальное подключение всеми пятью профилями и совместимость с конкретными версиями клиентов. Задействованы mock CLI, а не реальные VPN-сеансы.
- Не проверены HTTPS по IP, certbot renew, systemd, UFW, внешние UDP/TCP порты, NAT, IPv6 leak, нагрузка на 1 vCPU / 1 ГБ RAM.
- Нода-агент пока не разворачивает VPN; каскады и failover относятся к этапам 4–5.
- Динамические ограничения трафика/устройств, управление firewall из UI, полный контроль системных логов относятся к этапу 3 и последующим.
- **Старый `dist/arcvpn-linux-amd64` удалён из исходного архива**, потому что он не содержал новую серверную логику и встроенный React. Реальный релизный бинарник должен создаваться `scripts/build-release.sh` после установки npm-зависимостей и прохождения проверок.
