Исправления
Hysteria2 больше не получает пустую userpass-конфигурацию при отсутствии активных пользователей. Используется закрытый служебный credential, который не выдаётся клиентам; существующие доступы не меняются. Это исправляет отказ применения при отключении или удалении последнего пользователя.

«Сверить состояние» снимает блокировку неизвестной операции только после серверного подтверждения применения VPN. Ошибка создания сохраняет структурированный результат отката вместо неверного указания только на Xray.

Совместимость
Core/UI Linux amd64, минимум A10, прежний ключ подписи. Новых миграций БД нет. Если Hysteria уже зациклена в activating, после обновления выполнить: sudo systemctl stop arcvpn-hysteria.service. Фоновое применение панели запустит настроенную службу с исправленным конфигом; затем сверить состояние в UI.

Проверки
Реальный локальный Hysteria2: трафик, отзыв доступа и пустой список с отказом прежнему клиенту. Go regression и frontend build. VPS/systemd-восстановление проверяет администратор; production автоматически не менялся.
