# ArcVPN 0.4.4 — единая передача этапа 2 в Codex

Дата: **2026-11-04**. Статус: **source candidate / code handoff, не production**.

## Объём

Этот архив основан на 0.4.3. Его задача — объединить реализованную в Go программную часть автономного VPN с проверяемой логикой отката и передать исходники в среду, где доступны сборка React, upstream AmneziaWG 3.1 и реальные VPN-клиенты.

В проекте присутствуют серверная модель и генераторы для **VLESS Reality TCP, VLESS XHTTP Reality, Hysteria2, WireGuard, AmneziaWG 3.1**, независимые учётные данные, UI создания профилей, подписки, QR и конфигурации, SQLite, encrypted backup v2 и импорт v1/v2. Это не подтверждает реальное подключение к этим протоколам. Функции этапов 3–5 (управление UFW в UI, полнофункциональные удалённые VPN-ноды, каскады, автоматический client failover) здесь не реализованы.

## Внесённые исправления

1. `internal/app/protocols.go`: при отказе вспомогательного движка конфигурация Xray возвращается к предыдущей; отсутствие manager проверяется до изменения Xray; для включения/отключения протокола зависимости читаются до изменения флага SQLite.
2. `internal/xray/xray.go`, `cmd/arcvpn/main.go`: snapshot/restore Xray, команда `stop` в ограниченном root-helper для первоначального неуспешного применения, атомарная замена старого файла при неудачном restart, отказ от публикации потенциально секретного вывода валидатора.
3. `internal/engines/manager.go`: не включать stderr/stdout валидатора `wg-quick strip` в ошибки — там могут встретиться приватные ключи.
4. `internal/backup/backup.go`: в архиве v2 адрес протокола обязан совпадать с сохранённым адресом основного VPS; отклоняются протоколы без VPN, XHTTP на TCP/80 и учётные данные XHTTP, не совпадающие с UUID пользователя.
5. `internal/httpapi/portable.go`: прямой QR/экспорт VLESS по администраторскому API не предоставляется отключённому пользователю; прочие экспорты уже запрещали такой сценарий.
6. Новые сценарии проверок: `internal/app/protocol_rollback_test.go`; дополнительные тесты backup v2 и HTTP-экспорта при отключении; локальный скрипт `scripts/verify-stage2-local.sh`.

## Обязательные задачи Codex (строго в порядке)

1. На сетевой машине сохранить `frontend/package-lock.json` (из `npm install --package-lock-only --ignore-scripts`); проверить зависимости и закоммитить; затем выполнить `npm ci`, `npm run typecheck`, `npm run build`. Исправить ошибки без отключения TypeScript strict.
2. Запустить `scripts/verify-stage2-local.sh` и `tests/react_e2e.py` с **реальным** React bundle в Go. Проверить 320/390/768/1024/1440 px, формы протоколов/пользователей, экспорт/QR, авторизацию, восстановление, ошибки API, браузерную консоль и network waterfall. Если браузерный сценарий не проверяет операцию — расширить тест, а не писать PASS.
3. Собрать pinned upstream AmneziaWG 3.1 через `scripts/build-amneziawg.sh` на Linux с Go >=1.25, проверить `awg`, `awg-quick strip`, userspace и source distribution; подтвердить фактическую версию командой, не только SHA manifest.
4. Собрать релиз `scripts/build-release.sh`, проверить `dist/SHA256SUMS`, `dist/arcvpn-linux-amd64 frontend-check`, пути config/библиотеки/архитектуру. **Не публиковать** артефакты, пока не подтверждены происхождение, конфигурации и лицензии.
5. На отдельном тестовом VPS с консолью провайдера проверить `sudo bash install.sh`, HTTPS-сертификат на IP (без `-k`), systemd/UFW/SSH/обновление сертификата. Проверить реальные подключения с другого устройства: VLESS TCP, XHTTP, Hysteria2, WireGuard, AmneziaWG 3.1. Включить/отключить каждого пользователя, вернуть старую конфигурацию при ошибке, проверить NAT, DNS, MTU и изоляцию ключей.
6. Полностью восстановить зашифрованный архив ArcVPN v2 на втором тестовом сервере, проверить все ключи, токены, пользователей, профили и сертификаты. Отдельно проверить импорт v1. Если IP новый, запланировать изменение адресов и подписок; старые IP-ссылки не могут магически сохраниться.
7. Зафиксировать доказательства с версиями и санитизированными логами в `docs/implementation-status.md`; после исправлений запустить всё повторно. Только затем менять статус этапа на `EXTERNAL_ACCEPTED`.

Полная инструкция по реальной приёмке: `docs/testing/stage2-codex-handoff.md`. Требования к интерфейсу и автономному VPN: `docs/planning/acceptance.md`, `docs/features/inbounds-and-protocols.md`.
