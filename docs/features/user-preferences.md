# Пользователь: настройки и назначения локальных протоколов

8 ноября 2026. Источники реализованы локально; внешняя VPN-приёмка не выполнена.

## Контракт

`GET /api/users/{id}/preferences` возвращает `{name,preferences}`. `PUT` принимает `{name,preferences,expected_version}`; session+CSRF обязательны. Preferences: version, group, comment, title, access_mode(subscription/direct), direct_kind, allowed_kinds. Имя1–60 Unicode-символов, группа до50, комментарий до220, title до120 на сервере/25 в текущей форме и Happ header. Контрольные символы отклоняются. Пустое название подписки использует «ArcNet · имя».

`allowed_kinds:null` сохраняет legacy-доступ ко всем текущим/будущим протоколам. `[]` явно запрещает все локальные протоколы. Список содержит уникальные значения vless-reality/vless-xhttp/hysteria2/wireguard. DirectKind обязан входить в разрешённые при явном списке. Режим выдачи — предпочтение UI, не отзыв старого subscription token и не самостоятельное разрешение протокола. UUID, ключи и токены не перевыпускаются.

## Хранение и применение

SQLite migration добавляет `users.preferences TEXT NOT NULL DEFAULT '{}'` через PRAGMA/ALTER, идемпотентно; новые и старые записи получают совместимый default. Контроль ревизии внутри транзакции защищает от устаревших форм. Rename uniqueness остаётся ограничением БД. Metadata-only изменение не запускает engines.

Изменение назначений сериализуется application mutex, сохраняет новую policy и вызывает существующий runtime pipeline. TCP и XHTTP получают раздельные clients, Hysteria identities и WG peers выключаются согласно policy. Public links/export/QR используют отфильтрованный состав; устройства наследуют назначения владельца, WG export дополнительно проверяет разрешение. При apply failure восстанавливаются имя/policy и прежняя runtime конфигурация; rollback failure не замалчивается. Compensation увеличивает revision, чтобы старый клиент не перезаписал восстановленное состояние.

Эта версия — local-only: явные назначения нельзя сохранить при managed nodes или pending enrollments. Создание enrollment блокируется, пока есть явные назначения; верните всем «Все, включая новые» перед подключением нод. Это временное ограничение до отдельного ACK/reconcile enforcement. Активные cascade leases сохраняют прежние transaction guards. При legacy AmneziaWG изменение назначений запрещено; сохранённые ключи не удаляются.

## Backup

Формат14 переносит preferences вместе с именем и identities, включая различие null/пустой список. Читает1–13 с legacy default. Старые версии ArcNet не читают14: до обновления сохранить прежнюю резервную копию, не рассчитывать на откат одного бинарника после миграции. В архивах старого формата ненулевые новые preferences не принимаются. Архив14 с restricted preferences и нодами отклоняется. Восстановление/компенсация удаления пользователя сохраняет preferences.

## UI и ограничения

Управление открывает новую вкладку «Настройки»: имя, название подписки, режим выдачи, разрешённые подключения, группа/комментарий в Advanced. Пакет, срок и доступ перенесены в единый редактор с одним сохранением (см. дополнение ниже). Группа участвует в поиске. Прямая выдача выбирает предпочтительный URI-профиль, конфигурация WireGuard остаётся отдельным файлом.

В первом блоке НЕ выполнялись bulk и scheduler; bulk включение/отключение добавлено ниже. Пока НЕ выполнены scheduler сбросов, наблюдаемые session/IP limits, пользовательские графики/онлайн, несколько профилей одного kind, remote enforcement и полная структура всех экранов v6. Эти элементы нельзя показывать как работающие только на основании текущего редактора.

## Единый редактор и массовый доступ

`GET /api/users/{id}/editor` читает согласованный snapshot имени/enabled/preferences/package без ключей. `PUT` принимает `UserEdit`: имя/preferences, expected_version, expected_enabled, enabled и необязательный package {quota_bytes,expires_at,expected_version,reset_usage}. Все изменения выполняются одной SQLite-транзакцией; конфликт имени/версии/пакета откатывает всю запись. UUID и subscription token сохраняются. Конечный пакет и новый период сохраняют существующие coverage/fresh-counter gates; обычная правка имени не требует доступности движков.

Для этого нового API используется существующая desired-state модель пакетов: при сбое runtime все настройки остаются согласованно сохранёнными, state=apply_failed, worker повторяет применение. HTTP отвечает saved=true с runtime_state; UI показывает неподтверждённое применение и блокирует повторную отправку сохранённой формы. Это отличается от старого preferences-only API с компенсацией. Отзыв действующего туннеля НЕ гарантируется до успешного применения. Digest учитывает разрешённые протоколы; pending retry выполняется даже при неизменном digest. Секреты в digest не сериализуются.

`POST /api/users/bulk-access` принимает enabled и items [{id,expected_version,expected_enabled}], от1 до100 уникальных пользователей. Session+CSRF; транзакция проверяет каждого, изменяет всех либо никого, повышает preferences version и оставляет те же пакеты/ключи/подписки. Runtime применяется один раз; тот же явный pending статус. Выбор всех относится только к видимому фильтру; поиск/смена фильтра снимают выбор. Перед применением показаны действие и количество. Массовое удаление, массовые пакеты и массовое создание не добавлялись.

UI использует общие Dialog/Button/Field/Advanced/Notice и семантические DS-токены. В редакторе доступ/пакет/срок/подписка/подключения; группа/комментарий/новый период — в раскрываемом блоке. Отдельная вкладка редактирования пакета убрана из карточки, прежний API и компонент сохранены для совместимости. Наблюдаемые сессии и принудительные IP/device limits остаются отдельной незавершённой задачей.

## Таблица и массовые сценарии — продолжение 8 ноября

Сортировка по ID/имени/созданию/расходу/сроку, направление и фильтр по фактическим группам. Неизвестный расход остаётся в конце сортировки; не подменяется нулём. CSV выбранных либо видимых строк — UTF-8 BOM, quoting и защита от spreadsheet formula injection; без UUID/ключей/URL подписок.

`POST /api/users/bulk-create`: names[1..100], group. Все пользователи и protocol credentials создаются в одной транзакции, затем один runtime apply. Дубли имён и ошибка генерации ключей отменяют весь batch; ответ содержит только IDs/count/runtime_state. Начальные настройки аналогичны обычному созданию: включены, без лимита/срока, legacy-доступ ко всем протоколам; UI явно описывает это до создания. Повтор после потери ответа не создаёт дубли из-за UNIQUE name — нужно перечитать список.

`PUT /api/users/bulk-edit`: items[{id,expected_version,expected_enabled,package_version}], changes{quota_bytes?,expires_at?,group?,connections?:{allowed_kinds}}. Пропущенные поля не меняются. Ноль quota/expiry снимает ограничение. Connections null-list возвращает все текущие/будущие, [] отзывает все. Если direct_kind исключён из нового состава, предпочтительная выдача становится subscription. Счётчики/ключи не сбрасываются; конечные пакеты требуют свежей полной статистики. Конфликт любой записи отменяет весь batch. Metadata-only группа не перезапускает движки. Сохранённые изменения используют тот же pending/retry сценарий.

## Расписание пакета — локальная реализация

Package содержит необязательный reset_schedule {frequency:daily|weekly|monthly,timezone:IANA,next_at:serverUnix}. В PUT editor.package дополнительное поле schedule {frequency,timezone}; frequency=none выключает расписание. Пропущенный schedule сохраняет прежнее. Next_at из клиента не используется: сервер вычисляет следующую календарную границу. Daily — 00:00 следующего дня, weekly — понедельник, monthly — первое число. Не фиксированные 24часа: учитывается IANA/DST; tzdata встроена в Go как fallback.

Единственный RunUsage-loop после успешной коллекции вызывает ResetDuePackages. Проверяются свежесть всех источников, отсутствие нод и cascade lease; при stale-счётчиках сброс откладывается. Пропущенные границы после простоя объединяются в один reset: period/version повышаются, totals обнуляются, next_at переносится в будущее. Повтор/откат часов не сбрасывает дважды. Expiry, enabled, UUID, токены и checkpoints не меняются; физический счётчик не обнуляется, последующий delta продолжает учёт. Новый ручной период также переносит next_at в будущее. Фоновый runtime применяется существующим retry pipeline.

Schedules пока local-only без нод/pending enrollment/неподдерживаемых движков. Enrollment и применение несовместимых протоколов сохраняют guards; импорт backup с schedules и нодами отклоняется. Новый encrypted backup —15, читает1–14; старые сборки не читают15. Не выполнять откат одного бинарника с ожиданием совместимости нового backup.

Массовое удаление, телеметрия/online/IP-enforcement и несколько подключений одного kind остаются незавершёнными. Расписание не добавляет автоматическое продление срока.
