# Feature: серверы, предварительные проверки и SSH-установка из UI

**Статус 2026-11-04:** SSH bootstrap, Go agent/revision/rollback, UI, локальный CLI install, SSH uninstall, signed upgrade и node rebind реализованы на уровне исходников 0.6.1, но **этап 4 частично завершён** (нет полноценного preflight network/diff, real VPN probe, React typecheck/E2E и внешних VPS проверок). См. [реальный code handoff](../release-0.6.1-stage4-continuation.md) и [операционные ограничения](../ops/stage4-nodes.md). Историческое первоначальное требование: нужно полное управление нодами, а не telemetry-only. См. [аудит](../audits/2026-11-04-pre-stage4.md) и [чеклист](../planning/stage4-checklist.md). **Целевой сценарий:** администратор вводит доступ к VPS, система безопасно устанавливает агент/Xray, проверяет VPN и показывает ноду в общей схеме/таблице.

## 1. Режим без дополнительных нод

- `standalone`: Go-панель локально управляет Xray; отдельный агент **не требуется**. Подписки, пользователи, HTTPS, firewall, мониторинг и подключения работают на одном VPS.
- `hybrid`: та же панель одновременно обслуживает VPN и управляет внешними нодами.
- `controller`: панель без локального Xray, опционально и только по явному выбору.
- `node`: Go-агент + Xray без веб-панели.
- Роли нод не связаны со страной или порядком установки. Каскад не обязателен.

## 2. Поддерживаемое окружение и preflight

Источник истинных минимальных требований — **проверенная матрица совместимости**, а не фиктивный hard-coded список. Первоначальный ориентир для тестов: Linux Ubuntu LTS / Debian Stable, `amd64`/`arm64`, systemd, `1 vCPU / 1 ГБ RAM` для небольшого standalone; фактические минимумы подтвердить испытаниями. Для диска, числа файловых дескрипторов, сети и версии ОС определить минимумы по стенду и опубликованным релизам. Не утверждать произвольный «обязательный минимум 20 ГБ».

До установки обязательно проверить:

| Проверка | Что показать пользователю |
|---|---|
| ОС и архитектура | Распознана/поддерживается/нужна ручная установка |
| CPU/RAM/Swap/диск | Фактические значения, предупреждение при недостатке ресурсов |
| Доступ SSH | Адрес, порт, имя пользователя; host key fingerprint и доверие |
| Системные права | Возможность выполнить конкретный bootstrap (root или подтверждённый sudo) |
| Сеть | Доступ к репозиториям и управляющему endpoint, IPv4/IPv6, NAT |
| Порты | Конфликты с SSH, панелью, Xray и другими сервисами |
| Порт 443 на одном IP | Совместимость HTTPS панели, Reality/Xray, выбранного ACME challenge; конфликт блокирует неосторожную автоматизацию |
| Firewall | UFW/nftables/другой firewall/облачные правила, IPv4/IPv6 |
| Пакетный менеджер | Замки, незавершённые обновления, допустимость изменений |
| Время и сертификаты | Корректное время, возможность доверенной проверки TLS/ACME |
| Уже установленное ПО | Найденный Xray/3x-ui/другая VPN, предложить безопасный отдельный режим |
| Существующий доступ | Как администратор вернётся при неудаче; доступная консоль VPS-провайдера |

**Блокирующие ошибки**: не подтверждён host key, невозможно сохранить удалённое управление, неизвестный конфликт сервисов, нет необходимых прав, небезопасный сетевой план, неподдерживаемая ОС. Предупреждения требуют явного действия, а не silent bypass.

## 3. Мастер «Добавить сервер»

1. **Подключение:** название, IP/домен, SSH порт (по умолчанию 22), пользователь, ключ/пароль. UI не сохраняет секреты без отдельной явной политики; предпочтительнее SSH-ключ.
2. **Проверка подлинности:** предъявить host-key fingerprint и подтвердить **из доверенного канала** (консоль провайдера/известный ключ). TOFU сам по себе не защищает первый контакт от MITM.
3. **Проверка VPS:** система показывает перечень поддержанных пунктов, ошибок, конфликтов.
4. **Назначение:** независимый VPN, вход, выход, резерв, универсальный; можно не выбирать каскад. Если выбирается каскад, направление произвольное (A→B либо B→A).
5. **Профиль и порты:** рекомендованные безопасные значения заполняются автоматически; расширенный режим позволяет изменить каждый допустимый параметр и увидеть последствия.
6. **План действий:** просмотр командных последствий *без публикации секретов*: файлы/службы, firewall, пользователей ОС, открытые порты, изменение SSH, DNS/TLS, возможности rollback.
7. **Установка:** шаги с серверными событиями и прогрессом, возможность закрыть страницу без отмены server-side операции.
8. **Проверка:** config test, служба, firewall, внешний handshake/egress по профилю, агент identity и управление.
9. **Результат:** `Готово` только после подтверждения сервиса; `Частично` с точной ошибкой; `Откат` для управляемых изменений.

## 4. Bootstrap и доверие

- SSH-соединение настраивать с безопасной проверкой host key; запрет `InsecureIgnoreHostKey`.
- Проверять, что выбранный адрес/порт подпадает под сетевую политику установщика; ограничивать SSRF к metadata/IP/loopback/link-local и внутренним сервисам. Разрешение частного адреса — только явно по политике с повторной авторизацией.
- Не записывать SSH-пароль/приватный ключ в SQLite, логи, UI response, child-process argv, crash dumps. Не помещать секреты в командную строку процесса. Секреты живут ровно пока нужны для SSH bootstrap.
- Привилегированное действие ограничено отдельным setup helper, который устанавливается и удаляется либо переходит в минимальную роль. На удалённой ноде агент не должен иметь универсальный shell RPC.
- Узлу выдаётся индивидуальная идентичность через короткоживущий одноразовый enrollment proof, привязанный к операции установки и ожидаемой ноде. После регистрации — взаимно аутентифицированный канал с ротацией/отзывом.
- Агент инициирует исходящее соединение к панели/управляющему endpoint. Когда панель недоступна, Xray работает с `last-good`.
- Управляющий endpoint HTTPS требуется даже при отсутствии домена, но выбор ACME и способ проверки IP нужно подтвердить практическими испытаниями.
- Пакеты: pinned versions, подписанные артефакты или проверяемые digest из доверенного канала; никаких скачанных «последних» shell scripts без проверки.

## 5. План установки на VPS

| Этап | Возможные изменения | Проверка / компенсация |
|---|---|---|
| Preflight | Только чтение | Никаких изменений ОС |
| Stage files | Временные файлы и service units | Удаление только созданных файлов |
| Identity | Сертификат/ключ ноды | Отозвать enrollment при ошибке |
| Firewall | Добавить **managed** правила | Scheduled rollback + independent probe |
| Xray | Создать профиль и validated config | Сохранение last-good, безопасное применение |
| Agent | systemd-сервис + конфигурация | Подтверждение защищённого канала, остановка/rollback |
| Activation | Публикация endpoint в подписку | Только после внешнего теста и готовности маршрута |

Rollback не может гарантировать восстановление VPS при потере питания/внешнего firewall; показывать фактическое состояние и доступные provider rescue actions.

## 6. Управление установленной нодой

- Роль, имя, группа, IP, версии, окружение, ресурсы, health, applied/desired revision, last_seen, последнее успешное внешнее тестирование.
- Управление Xray и совместимыми обновлениями, перезапуск, отключение, drain, вывод из подписок, замена VPS, удаление.
- Отдельные состояния: `SSH доступен`, `Агент в сети`, `Xray запущен`, `VPN доступен`, `Маршрут исправен`.
- Полное удаление требует явного выбора: удалить из панели / удалить управляемые файлы с VPS / оставить работающий VPN без управления. Не удалять чужие сервисы.
- Безопасный сценарий миграции: новая нода поднимается, проверяется, только затем переключается логический endpoint и обновляются подписки/маршруты.

## 7. Ошибки и тесты

- Нет доступа SSH, неправильный host key, нет sudo, порт занят, несовместимая ОС, недоступный интернет, сертификат не выдан, IP заблокирован, пакетный менеджер занят.
- Interrupted browser/Go restart/agent restart: operation journal позволяет продолжить/откатить без дублирования и повреждения системы.
- UFW частично применён: SSH сохраняется либо rollback с понятным статусом; внешняя проверка отличает локальные и облачные блокировки.
- Другой VPN уже использует порт: предложить альтернативный порт, **не останавливать чужой процесс автоматически**.
- Производительность: installation worker с ограниченным числом конкурирующих задач; нет постоянно активного SSH session на каждую ноду.

## Состояние функциональности 0.6.2 (исходники, не acceptance)

Добавлены read-only HTTPS egress preflight и предупреждения о UFW/nft, независимая сверка SHA-256 уже установленных root-owned бинарников перед запуском, read-only recovery receipt после неоднозначного SSH результата. Внешний VPN-probe и собственно публикация удалённых endpoint всё ещё **не реализованы**. Подробности: [0.6.2 source handoff](../release-0.6.2-stage4-continuation.md).
