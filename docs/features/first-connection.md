# Первый вход и подключение

Контракт исходников от 2026-11-07. UX использует идеи 3x-ui и [Impeccable](https://github.com/pbakaus/impeccable), реализация самостоятельная, без установки новых зависимостей.

## Продолжение: управление протоколами ArcNet

Публичное имя интерфейса — ArcNet. «Протоколы» настраивают локальные listeners, «Пользователи» управляют выдачей доступа. Основное меню: обзор → протоколы → пользователи → серверы → маршруты; журнал, резервные копии и настройки — внизу. Общие SVG-иконки, интервалы и компоненты desktop/mobile заменяют текстовые псевдоиконки. Имена команд/служб, wire formats и пути `arcvpn` сохранены для совместимости. Настройки безопасности и аккаунта находятся в «Настройки».

В созданном REALITY TCP/XHTTP редактируются порт, SNI и target. Hysteria2/WireGuard — порт; имя TLS Hysteria2 ограничено существующим IP-сертификатом. Адрес локального сервера общий и в этой форме только для чтения. Смена типа, имени/адреса сервера и ключей не добавлена как скрытая миграция. При одинаковых target/SNI изменение SNI предлагает тот же target, отдельное значение target доступно в расширенных настройках. Перед применением виден diff; успешное сохранение закрывает диалог и обновляет список.

`GET /api/vpn` теперь возвращает enabled/revision, `GET /api/protocols` — revision каждого профиля; ответы no-store. `PUT /api/connections/{kind}` принимает revision/port/target/sni/enabled. Непустая актуальная revision обязательна: сравнение под application mutation lock отклоняет устаревшую форму (409), не вращает ключи/ID/токены и не меняет credentials. Сервер проверяет тип, hostname/порт, TLS-ограничения и конфликты TCP/UDP, включая panel/ACME/private stats ports. Режим обслуживания проверяется до записи и повторно перед runtime apply. Ошибка применения восстанавливает сохранённые параметры и runtime; сбой восстановления возвращается отдельно без сырых секретных диагностик. Изменение может кратко прервать подключения через существующий общий apply pipeline; после смены endpoint клиенту нужно обновить подписку/конфигурацию.

Включение/отключение и удаление имеют отдельное подтверждение. Удаляется только отключённый профиль с актуальной revision через `DELETE /api/connections/{kind}`. Последний локальный профиль при наличии пользователей сохраняется отключённым как адресная identity. REALITY дополнительно не удаляется при legacy AmneziaWG-зависимости. Пользователи/остальные профили не удаляются; удаление протокола всё же уничтожает его собственные ключи/credentials, что явно показано в подтверждении. Старые API включения/удаления дополнительных протоколов сохранены для совместимости.

В подписке/QR больше нет обязательного выбора Happ/Streisand: ссылка импортируется в совместимое VPN-приложение. Выбор конкретного набора протоколов для пользователя, график, дальнейшие сессии/full updater и firewall остаются отдельными пунктами плана. Это не лечение отложенного VLESS-handshake на мобильной сети. [Проверки этого блока](../testing/local-results/stage5-2026-11-07-connection-management.md).

Дополнение по дальнейшим замечаниям: мобильное меню открывается бургером в native modal drawer с теми же пунктами и нижними настройками, закрывается при переходе и desktop resize. Настройки сгруппированы «Аккаунт / Сервер / Обновления»; данные групп запрашиваются при выборе, формы не размонтируются при переключении. Создание раздельно показывает поддерживаемые протокол/транспорт и применяемую защиту, не предлагает произвольные несовместимые сочетания. В расширенных параметрах редактора можно отдельно открыть существующий SNI-picker; выбор кандидата меняет только черновик, затем нужен diff/явное применение.

Подписка передаёт `Profile-Title: base64:<UTF-8>` со значением «ArcNet · имя пользователя», очищенным от control characters и ограниченным 25 Unicode-символами. Это соответствует [документации Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/app-management.md#standard-parameters), HTTP body остаётся прежним URI list. Название возвращается в authenticated user/device subscription metadata и показывается в окне выдачи; token/auth/no-store/revoke gates сохраняются. Отдельное название, редактируемое независимо от имени пользователя, остаётся в следующем блоке карточки пользователя. Реальное отображение/обновление имени в Happ/Streisand ещё не проверено; название не скрывает настоящий IP от сетевого наблюдателя.

## Первый администратор

Чистая установка печатает адрес HTTPS-панели и одноразовый код на 15 минут. В браузере владелец вводит код и выбирает логин/пароль; открытой регистрации нет. Истёкший код заменяется командой `sudo arcvpn setup`. Уже существующий администратор не заменяется: эта команда завершается отказом.

В SQLite хранится только SHA256 кода. Создание единственного администратора и погашение кода атомарны; проверяются origin, размер ввода, ограничение попыток и число одновременных password KDF. После создания нужен обычный вход. Сначала логин/пароль, затем отдельный шаг TOTP только при включённой 2FA; до правильного TOTP сессия не выдаётся.

В «Безопасность → Учётная запись» действующий администратор меняет логин/пароль с подтверждением текущего пароля. Изменение отзывает сессии и сохраняет включённую 2FA. Перерегистрация поверх существующих данных не нужна.

## Подключение и выдача

«Подключения» — компактная таблица и одна кнопка добавления. В диалоге отображается форма выбранного протокола с предложенными значениями; редкие параметры скрыты. Поддержанный новый выбор: REALITY TCP, REALITY XHTTP, Hysteria2, WireGuard. Старые AmneziaWG-данные не удаляются.

После создания: «Пользователи → Добавить → Подключить». Для URI-протоколов основной способ — подписка и её QR, отдельный URI доступен дополнительно. Подсказки ориентированы на Happ/Streisand; поддержка зависит от версии клиента. Для WireGuard сохраняется выдача `.conf`. QR создаётся локально, требует сессию и повторно проверяет доступ; отзыв устройства делает его QR недоступным.

## SNI и ошибки

Встроенный список расширен до 12 предложений. Подписанный внешний каталог и собственный список сохраняются; новая внешняя зависимость не обязательна. За одну проверку — до четырёх кандидатов. Одинаковый выполняющийся запрос повторно использует job, другой запрос на занятый сервер получает отдельную понятную ошибку. Отмена локальной проверки освобождает job. Проверка пробует доступный адрес через существующий SSRF-safe dialer, сохраняя TLS/certificate/HTTP2 gates.

Нет универсального «лучшего SNI»: пригодность проверяется с выбранного сервера. Успешный TLS-target probe не доказывает VPN handshake. Ошибки генерации ключей, проверки конфигурации и запуска различаются без публикации сырых диагностик/ключей. Парсер Xray принимает в том числе `Password (PublicKey)`; этот формат подтверждён оператором на Xray 26.10.31.

## Общие взаимодействия — 2026-11-07

Общие disclosure используют chevron справа/focus/reduced motion. Диалоги закрываются по фону/Escape с проверкой busy/unsaved; редактор порта/SNI и пакет используют фактический diff. SNI-результаты без пригодного измерения не имеют кнопки выбора; ошибка не меняет действующий SNI. Адрес подключения подписан как адрес клиента, отличающийся от SNI. Реальные protocol settings этим UI-блоком не расширены.

## TLS fingerprint и расширенные настройки VLESS

В TCP/XHTTP создании и редакторе основной путь сохраняет автоматические параметры, advanced предлагает TLS fingerprint клиента: chrome(default), firefox, safari, ios, android, edge, 360, qq, random, randomized. Это профиль ClientHello для VPN-клиента, не смена браузера ОС и не гарантия обхода ограничений. Список опирается на [официальный TLS contract Xray](https://github.com/XTLS/Xray-docs-next/blob/main/docs/config/transports/tls.md) и [REALITY](https://github.com/XTLS/Xray-docs-next/blob/main/docs/config/transports/reality.md); unsafe и произвольные строки не разрешены. Поддержка конкретным Happ/Streisand требует проверки на устройстве.

Создание принимает optional fingerprint; PUT connection edit — optional fingerprint/path. Отсутствующее поле сохраняет прежнее значение, пустой fingerprint возвращает default Chrome. Path меняется только в XHTTP и проходит прежний protocol validator. Revision включает preference. FP хранится транзакционно в существующей settings (ключ client_fingerprint:kind), без новых колонок/таблиц; delete/replace/restore очищают старую preference в той же транзакции. TCP и XHTTP могут иметь разные профили.

Все прямые/подписные/device URI и QR, использующие прежние генераторы, получают fp. Client-only смена не вызывает apply/restart; пользователь обновляет подписку. Порт/SNI/target/path идут через прежний apply/compensation. Приватные ключи, UUID и tokens не меняются от выбора fingerprint. Публичный ключ/Short ID показаны read-only; новые ключи создаются прежним server-side генератором при создании протокола. Скрытой ротации и вывода private key в API нет.

Backup13 переносит TCP/XHTTP preference и сохраняет при RemapAddress; reader принимает1–12 с default Chrome. Поле fingerprint запрещено под legacy version1–12. Старые сборки не читают backup13, перед обновлением сохранить старую резервную копию. Существующие keys/учёт/подписки не мигрируют.

Доступные сейчас параметры: адрес(read-only общего сервера), порт, SNI/target, TLS fingerprint, XHTTP path, публичные параметры ключей. Параметры транспорта/flow/REALITY policy и остальные расширенные настройки добавляются только по типизированной матрице совместимости с пояснениями; raw JSON и неподдерживаемые сочетания не заменяют реализацию. Каскадный outbound fingerprint и удалённые ноды этим блоком не меняются.

## Клиентские параметры — локальные исходники 8 ноября

В редакторе XHTTP поддерживаются auto (по умолчанию), packet-up, stream-up, stream-one. Значение передаётся в mode ссылки/подписки; сервер продолжает принимать auto. Для WireGuard доступны клиентские MTU1280–1500 (default1280), до4 IPv4 DNS (default1.1.1.1) и keepalive0–65535 (default25;0 выключает). Это настройки экспортируемого .conf, не изменение серверного интерфейса, NAT или firewall. После сохранения требуется обновить подписку / повторно импортировать файл. Поддержка XHTTP mode конкретным Happ/Streisand и сетевой результат требуют внешней приёмки.

client_options — типизированный объект API PUT /api/connections/{kind}; поле отсутствует — сохранить прежние настройки, {} — вернуть defaults. Некорректные и чужие протоколу поля отклоняются, DNS не принимает hostname/перевод строки/IPv6. Настройки живут в существующей settings под client_options:{kind}, сохраняются/удаляются и восстанавливаются в одной транзакции с профилем. Оpaque revision учитывает options; CSRF/session/paused gates сохранены. Изменение только fingerprint/options не перезапускает движок и не читает весь список пользователей. Совмещённое server edit использует прежний apply/rollback, включая возврат старых options. Приватные ключи API не принимает и не раскрывает.

Backup16 переносит options; reader принимает1–15 с прежними defaults, ненулевые новые настройки под legacy version отклоняются. Старые сборки не читают16: сохраняйте старый backup для возврата. DDL/units/helpers не меняются.

ALPN не добавлен фиктивным полем для REALITY: [официальный RealityObject](https://xtls.github.io/config/transports/reality.html) описывает fingerprint/serverName, без отдельного alpn. Flow TCP пока фиксирован xtls-rprx-vision, XHTTP без flow; его переключение требует согласованного изменения сервера/клиента. Hysteria2 показывает существующие TLS/SNI и обязательную проверку сертификата; QUIC/masquerade/bandwidth не реализованы этим блоком. XHTTP режимы сверены с [upstream XTLS](https://github.com/XTLS/Xray-core/discussions/4113), WireGuard поля с [wg-quick upstream](https://github.com/WireGuard/wireguard-tools/blob/master/src/man/wg-quick.8) и [keepalive](https://www.wireguard.com/quickstart/).

Остаются: server-side advanced fields, ротация ключей отдельной операцией, автоматическое предложение SNI/fingerprint с diff, несколько независимых подключений одного вида, firewall/full updater и реальная диагностика WG. IPv6-трафик/защита от обхода IPv4-only WG на клиенте не решены этими client options; не заявлять отсутствие утечек или production acceptance.


## Серверные параметры и v7 — локальные исходники 8 ноября

server_options в PUT /api/connections/{kind} поддерживает sniffing для VLESS TCP/REALITY и XHTTP (HTTP/TLS, routeOnly=true), udp_idle_seconds2–600 и quic_idle_seconds4–120 для Hysteria2. Отсутствующий объект сохраняет прежние overrides, {} возвращает defaults: TCP sniffing=true, XHTTP без sniffing, Hysteria UDP60с/QUIC30с. Параметры другого протокола отклоняются. Значения хранятся в settings серверной части и входят в revision; обновление выполняется под existing mutation lock, validate/apply/rollback. При отказе возвращаются старые options, credentials и runtime. Equal сравнивает значения nullable boolean, а не адреса указателей: неизменённый sniffing не превращает client-only update в restart.

Backup17 переносит TCP и protocol server_options, читает1–16 с defaults; ненулевые server_options под старой версией запрещены. Для обновления/возврата сохраняйте предыдущий backup: старые сборки17 не читают. DDL, root helpers, SSH/UFW и systemd units этим блоком не меняются.

Интерфейс использует действующие тёмные токены/компоненты v7, SettingsSection/Properties/Advanced/Dialog. Hysteria2 показывает только свои настройки; VLESS — свои. Перед применением виден diff с различением server restart и client export. Карточка показывает текущие серверные overrides. Кнопка «Обновить параметры» открывает существующий проверяемый подбор SNI и прокручивает форму к нему, учитывая reduced-motion. Выбранный результат меняет лишь черновик SNI/target, не keys/fingerprint/port; фактическое применение требует отдельной кнопки. Автоматический подбор fingerprint из сети пользователя не реализован и не имитируется.

Диапазоны Hysteria сверены с [app/v2.6.3 upstream config](https://raw.githubusercontent.com/apernet/hysteria/app/v2.6.3/core/server/config.go); значения JSON — udpIdleTimeout и quic.maxIdleTimeout, [документация](https://v2.hysteria.network/docs/advanced/Full-Server-Config/). Поддержка sniffing/routeOnly — [Xray inbound](https://xtls.github.io/en/config/inbound.html). На реальном установленном движке и изолированной VM с rollback не проверено: этот gate обязателен до приёмки/релиза.

Остаток этого блока уточнён ниже; полный advanced редактор и визуальная приёмка v7 не объявляются завершёнными.

## Flow, смена ключей и Hysteria2 — локально 8 ноября

TCP VLESS: Vision по умолчанию либо без flow; серверные shared/device clients и URI меняются согласованно, REALITY остаётся включённым. У XHTTP flow не задаётся. [Контракт Xray](https://xtls.github.io/en/config/inbounds/vless.html). Каскадные профили этим редактором не меняются.

REALITY TCP/XHTTP и WireGuard: отдельное «Сменить ключи» → план с количеством/первыми20 затронутыми пользователями → подтверждение. Учитываются и отключённые пользователи. CAS проверяет ревизию профиля и полный состав назначений. Обычное сохранение не меняет ключи; смена сохраняет UUID, токены подписок, пакеты и сроки. Старые профили нужно обновить. При ошибке применяется существующая компенсация metadata/runtime. Это не гарантирует восстановление после отказа самой компенсации; такая ошибка требует диагностики. Hysteria user passwords этой операцией не меняются.

На время редактирования/смены ключей конечные HTTP-ответы с подключениями буферизуются до4МиБ и проверяют версию публикации до/после чтения. При изменении возвращается503 без промежуточных ключей, Retry-After1. SSE не буферизуется. Backup export уже использует mutation lock. Это защита этих операций, не универсальная транзакция всех старых сценариев приложения.

Hysteria2: Salamander с автоматически созданным32-byte URL-safe секретом; секрет скрыт из публичного JSON, но нужен в bearer-подписке и зашифрованном backup. Повторное сохранение сохраняет секрет. Полоса0 означает auto, иначе1–100000Мбит/с; server up — получение клиентом, down — отправка. Это переговорный лимит каждого соединения Brutal, не гарантированное ограничение BBR/Reno или суммарной скорости пользователя. [Серверная конфигурация](https://v2.hysteria.network/docs/advanced/Full-Server-Config/), [URI](https://v2.hysteria.network/docs/developers/URI-Scheme/), [pinned app/v2.6.3](https://raw.githubusercontent.com/apernet/hysteria/app/v2.6.3/app/cmd/server.go).

Все поля сохраняются в существующих settings/ObfsKey без DDL и переносятся backup18; старые1–17 читаются, несовместимые новые поля под старой версией отвергаются. Произвольный masquerade proxy URL не добавлялся из-за отдельной SSRF-границы. Открыты: auto fingerprint, дополнительные поддерживаемые поля, duplicate inbounds, автоматический firewall/full updater, IP/device enforcement и серверная приёмка. [Проверки](../testing/local-results/rotation-hysteria-2026-11-08.md).
