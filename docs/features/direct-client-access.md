# Выдача отдельного подключения и подписки

2026-11-06. По просьбе пользователя UX ориентирован на сценарий 3x-ui, реализация собственная. У пользователя и устройства есть «Подключить»: выбор одного действующего URI, копирование и локальный QR. Подписка и её QR вынесены отдельно; для WireGuard используется .conf.

Список прямых URI берётся из текущего разрешённого набора SubscriptionLinks/DeviceLinks, включая подтверждённые опубликованные cascade entries. Ссылка указывает на входную ноду; дальнейший серверный путь может меняться без смены адреса/порта/ключей клиента. JSON подписки и спецклиент не требуются для обычного URI. Поддержка конкретного протокола зависит от установленного приложения/версии/ОС; телевизор должен иметь совместимый клиент.

`link_ids` — SHA256 соответствующих URI, а не credential в query string. `/api/users/{id}/qr?format=link&selection=<hash>` и `/api/users/{id}/devices/{device}/qr?selection=<hash>` требуют сессию, повторно читают разрешённые действующие links и генерируют SVG локально. Смена/отзыв доступа делает старую selection недействительной. No-store/CSP, без внешних QR-сервисов и передачи URI в адресной строке. Legacy format=vless/subscription сохранены.

Кнопка копирования имеет fallback: видимый текст ссылки можно выделить вручную, если браузер запретил clipboard. Списочный API устройств не раскрывает UUID/tokens; ссылки запрашиваются отдельно при явном открытии подключения.
