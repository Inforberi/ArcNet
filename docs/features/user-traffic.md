# Телеметрия пользователя: скорость и наблюдаемый трафик

8 ноября 2026, только локальные исходники. Online/session/IP enforcement не реализованы этим блоком.

## Сбор и достоверность

Существующий единственный `App.RunUsage` опрашивает локальные Xray TCP/XHTTP, Hysteria2 и WireGuard, по умолчанию с паузой5с. Коллекторы возвращают уже проверенные накопительные counters; после успешной записи в authoritative accounting они же передаются в независимый `usage.TrafficTracker`. Дополнительных запусков движков, сбросов счётчиков или коллектора на HTTP-запрос нет. Parent counter уже объединяет выданные device credentials; физических устройств отсюда не выводим.

Скорость = разница байтов / фактический интервал каждого источника, затем сумма разрешённых локальных потоков. Нужны две наблюдаемые точки одной identity/epoch и интервал не более20с. Первый замер, рестарт, пропуск источника, регрессия и смена identity не превращаются в ноль/пик. Ошибка одного требуемого движка делает общую скорость неизвестной. Состав ограничен разрешёнными протоколами пользователя. `complete_coverage=false` явно отмечает неполноту (например, ноды/AmneziaWG).

`last_activity_at` — время наблюдения увеличившихся счётчиков, не точное время последнего пакета, входа или подключения. Начальные ненулевые счётчики не считаются новой активностью. Нулевая скорость не означает offline. `online:null` всегда, пока не подключён подтверждающий session API. Показатель source/service health не заменяет VPN handshake.

## Память и история

Tracker принадлежит конкретному App и защищён отдельным RWMutex: чтение не ждёт полного engine apply под application mutex. Последние counters ограничены10000 пользователями/40000 потоками. История — глобальное кольцо16384 точки, последний снимок пользователя за минуту, выдаётся окно до2ч. При большом числе пользователей фактическая история короче2ч. Смена identity/удаление не раскрывают старые данные; откат часов очищает baseline/историю. Пропуски помечаются сегментами, график не соединяет их линией.

В SQLite не добавляются записи телеметрии каждые5с. История/последняя активность эфемерны: сбрасываются при перезапуске процесса, не входят в backup. Финансовый учёт/пакеты и checkpoints остаются прежними, не используют этот буфер.

## API и UI

`GET /api/users/traffic?ids=1,2&history_id=1`: admin session, no-store, до200 уникальных положительных IDs и4199 символов списка. SQL читает только существующие id/uuid по IN; UUID используется внутренне для проверки identity и не возвращается. Ответ: items{user_id,at,upload_bps,download_bps,window_seconds,segment,last_activity_at,status,online}, source, fresh_for=20, sampled_at, complete_coverage, history_persistent=false. Необязательная detail содержит одного выбранного пользователя и историю. Нет ключей, subscription URL, IP и arbitrary engine calls. Удалённые IDs не возвращаются.

Таблица рендерит25/50/100 строк; телеметрия текущей страницы плюс открытой карточки приходит одним batch query. Выбор строк по страницам сохраняется; «выбрать всех» относится к текущей странице, CSV сохраняет прежний экспорт выбранного/отфильтрованного набора. Карточка открывает «Основное» с текущей скоростью/активностью и графиком; единый редактор остаётся на вкладке «Настройки».

Общий `MonitoringProvider` переведён с SSE на polling по прямому уточнению владельца. Один clock на layout, active queries и cancelRefetch=false исключают повторный запрос уже загружаемого query. Следующий цикл после завершения предыдущего, минимум выбранного интервала5/10/15/30/60с. В hidden/offline polling остановлен, при возвращении возобновляется; history и общая настройка интервала перечитываются не чаще минуты. Backend SSE endpoint сохранён для прежних клиентов; новый UI его не открывает. TanStack polling behavior сверено с [документацией5.90.3](https://github.com/TanStack/query/blob/v5.90.3/docs/framework/react/reference/useQuery.md), установлена5.90.1.

UI учитывает возраст последнего ответа относительно server sampled_at, поэтому различие часов браузера и сервера не превращает свежую скорость в устаревшую. При ошибке запроса текущие значения неизвестны, история последнего ответа остаётся видимой с пояснением. Общий компонент `shared/TrafficChart` использует DS colors и keyboard/pointer поведение для обоих графиков.

## Не подтверждено

Live online, наблюдаемые IP/приложения/сессии, concurrent limits, remote user telemetry и реальные подключения не заявляются. Стенд18394 использует mock engines без реальной статистики — «Нет данных» там ожидаемо. Визуальная browser-приёмка заблокирована Work settings; performance микрозамер не является нагрузочным испытанием сервера.
