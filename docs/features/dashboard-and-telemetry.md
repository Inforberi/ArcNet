# Feature: дашборд и телеметрия

## Визуальная основа

См. [dashboard.png](../references/screenshots/dashboard.png). Сохраняем четыре metric cards CPU/RAM/Swap/Disk, график traffic, TCP/UDP sockets, статус Xray, uptime, версия и системные действия. Добавляем Node health, Route health, Subscription availability и список текущих ошибок.

## Определения

- `Online` — есть недавняя телеметрия/heartbeat; не доказывает доступность VPN из внешней сети.
- `Xray running` — процесс обслуживается; не доказывает корректный egress.
- `Route healthy` — внешняя проверка показала доступность нужного пути.
- `Unknown` — данные недоступны/устарели; не показывать как «0».

## Экономия ресурсов

Сбор системных метрик по расписанию с bounded частотой и агрегацией; SSE для активных админов, при отсутствии подписчиков не рассылать частые UI-обновления. Хранить суточные агрегаты вместо бесконечного сырого time series. Snapshot API предоставляет последнюю метрику + timestamp.

## Приёмка

Загрузить панель, отключить ноду, отключить Xray, выключить браузер; состояние в UI и реально изменившаяся частота запросов должны соответствовать документации. Процессы не создают новые безлимитные goroutine при каждой открытой вкладке.
