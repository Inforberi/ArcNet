# Feature: полный перенос ArcVPN между VPS через веб-панель

**Согласованное изменение (2026-11-04):** интеграция импорта **из 3x-ui не требуется**. Нужен собственный перенос **ArcVPN → ArcVPN**, похожий по удобству на выгрузку/восстановление 3x-ui, но с независимым документированным форматом и безопасной процедурой.

## Пользовательский сценарий

1. Старый VPS: `Настройки → Резервные копии → Создать` с выбором **полной** или **выборочной** копии.
2. Пользователь задаёт пароль шифрования и скачивает файл либо настраивает хранение копий вне текущего VPS.
3. На новом VPS выполняется стандартная установка ArcVPN одной командой.
4. На первом входе в `Восстановить из архива` пользователь загружает копию, вводит пароль, получает **предпросмотр** изменяемых объектов (без раскрытия ключей), предупреждения и конфликты версий.
5. Перед применением панель сохраняет recovery checkpoint, валидирует двигатели/конфиги, применяет миграции и показывает состояние каждого ресурса. При ошибке — откат базы/конфигураций до checkpoint; отсутствие отката обозначается ошибкой, а не успехом.
6. При смене IP новый адрес отражается в endpoint profiles. Старые URL подписок на утраченный IP **не могут продолжить работать** без заранее доступного резервного адреса/домена/перенаправления.
7. Новые и ранее подключённые ноды проходят re-enrollment там, где старые сертификаты/идентичности больше нельзя доверять; нельзя автоматически считать удалённые серверы управляемыми после восстановления файла.

## Состав полной копии

- Пользователи, внутренние и внешние UUID, credentials протоколов, лимиты, сроки, группы, настройки устройств и глобальные квоты (с явно обозначенной актуальностью).
- Токены и идентификаторы подписок, их назначение, набор профилей, publish revisions и резервные URL.
- Inbounds/outbounds/transport, ключи Reality и TLS при необходимости, маршруты, роли/топология нод, политики доступа/фейловера, provenance ручных overrides.
- Настройки панели, управляемые firewall policies, логирование и допустимые параметры системы, версионированная схема БД.
- **Не** включать: активные browser sessions, временные enrollment tokens, приватные SSH credentials, чужие файлы ОС, неприменимые сертификаты на старый IP.

При переносе секретов создавать отдельный encryption envelope (authenticated encryption, сильная KDF с солью и случайными параметрами в заголовке), проверять целостность **до любых изменений**, защищаться от zip-slip, zip bomb, malformed/cross-version импортов, и строго проверять права backup-файлов. Выборочный экспорт не должен скрытно терять зависимости (например, профиль без пользователя или маршрут без ноды).

## Текущее дополнение v4 — 2026-11-05

`internal/backup` экспортирует encrypted v4 с route drafts. Импорт проверяет граф и все node IDs до изменения состояния; ноды и маршруты заменяются атомарно. Версии маршрутов увеличиваются, чтобы формы, открытые до восстановления, получили CAS conflict. При ошибке применения движков возвращаются прежние черновики. Маршруты не активируются.

v1/v2/v3 поддерживаются и не заменяют существующие маршруты. При v3 замена нод, разрывающая текущие route references, отклоняется без частичных изменений. Пустой список v4 очищает маршруты явно. Preview показывает число маршрутов, версию и семантику замены. Восстановление архива без локального VPN пока не поддержано.

Это не полный перенос инфраструктуры: runtime/SSH lifecycle и реальные VPN-пробы не восстанавливаются. [Подробности и ограничения](../release-0.7.0-stage5-routing-ui.md).

## Известный текущий код

В `internal/backup` и `internal/httpapi/portable.go` есть **частичный** шифрованный экспорт и восстановление текущего VPN-состояния, с сохранением client/subscription IDs. Он **не является полной переносимой инфраструктурой** и не прошёл реальное восстановление на другом VPS. Ни управление набором всех движков/нод, ни сохранение всех маршрутов, ни внешний миграционный тест пока не подтверждены.

## Приёмка

- Полный и выборочный экспорт доступны через React UI, формат имеет версию, невозможен импорт с неправильным паролем или искажённым архивом, нет частичного применения.
- После восстановления в чистой VM совпадают клиентские UUID, subscription ID, лимиты, параметры и ключи без переноса сессий администратора.
- Смена IP правильно переиздаёт адреса/сертификаты; ошибочные старые ссылки не выдаются как действующие.
- Реальное VPN-подключение и подписка проверены через отдельный клиент; при недоступной ноде отображается `requires re-enrollment` вместо ложного `online`.
- Восстановление без исходного VPS возможно из сохранённого внешнего архива в пределах его актуальности. Локальный backup, потерянный вместе с VPS, не обеспечивает disaster recovery.
# Дополнение v5 — 2026-11-05

Экспорт теперь включает сохранённые traffic profiles (списки/порядок/DNS-намерение/enabled), отдельно от физических routes v4. Импорт v5 заменяет профили транзакционно и повышает ревизии для инвалидирования старых форм; v1–v4 сохраняют текущие профили. UI preview показывает замену и количество отдельно. Enabled не активирует runtime; диагностические SNI-задания и каталог не входят в VPN-state backup. [Контракт и ограничения](traffic-profiles-and-targets.md), [проверки](../testing/local-results/stage5-2026-11-05-profiles-targets.md).


## Дополнение v6 — 2026-11-05

Portable encrypted state переносит пакеты, период/расход, checkpoints и ограниченный журнал списаний. Импорт для того же UUID не уменьшает уже известный расход текущего периода и не возвращает checkpoint назад; legacy v1–v5 сохраняет surviving accounting. После restore source liveness сбрасывается до новой проверки. Лимит encrypted JSON — 64 МиБ, plaintext — 32 МиБ. Проверен round-trip 65536 debit rows; новые админские сессии/пароли в архив не входят. Ошибка удаления пользователя с apply failure восстанавливает credentials и accounting атомарно. Подробнее: [ADR-008](../adr/008-local-xray-traffic-packages.md). Это не восстановление runtime/VPS или доказательство точности трафика всех протоколов.
## Backup v7 — устройства

Зашифрованный payload переносит индивидуальные UUID/token, лимит и даты отзывов. Restore не возвращает местный отозванный доступ и общий ключ совпадающего пользователя; действующий местный лимит сохраняется. Архивы до v7 сохраняют устройства пользователей с теми же ID+UUID. Неподдерживаемые ноды/движки или превышение лимита после объединения отклоняют транзакцию. Preview явно показывает наличие устройств. [ADR-009](../adr/009-device-credentials.md).
