# Профили трафика и SNI-диагностика — локальный control plane

Дата: 2026-11-05. Код реализован локально; runtime маршрутизации, независимый VPN и приёмка VPS не заявлены. [ADR-005](../adr/005-traffic-profiles-and-target-diagnostics.md).

## Профили

- `/api/routing-profiles`: GET список, POST создать; `/{id}` PUT/DELETE с `expected_version`, GET `/{id}/export`. `/import` принимает `{archive:string}` и возвращает preview без записи; `/list-preview` — `{text:string}` с нормализацией/дедупликацией; `/check` — `{profile,address}`, чистая модель без DNS или сети. Все операции требуют сессию, изменения/проверки — CSRF.
- До 32 профилей, суммарно 2048 записей на профиль, JSON хранения 64 КиБ, импорт 256 КиБ. Условия domain/full, IP/CIDR, geoip/geosite. Неисполняемые неподдерживаемые regex/URL отклоняются. Одинаковые канонические записи в разных действиях запрещены. Первое совпадение по порядку групп; более ранние неизвестные Geo/DNS-условия дают `needs_dns_or_geodata`, без выдуманного результата.
- Выключение сохраняет списки и модель базового proxy, даже если дополнительное default_action — direct. DNS-поля остаются намерением. Никакие Geo-базы этим кодом не скачиваются и не считаются существующими.
- UI по умолчанию показывает профили; тяжёлый граф каскадов загружается отдельно. Диалог на мобильном экране, расширенные параметры свёрнуты. Закрытие сохраняет draft в памяти страницы; переход/перезагрузка может его потерять. 409 сохраняет форму, предлагается загрузить серверную версию. Поздний ответ проверки не показывается для изменённых полей. Импорт списка сравнивает канонические записи существующего текста и файла.
- Backup v5 переносит профили с отключённым runtime/publication. v1–v4 не удаляют текущие профили; невалидный импорт откатывает транзакцию. Восстановление повышает ревизии для защиты от старых форм.

## Кандидаты и проверки

- GET/POST `/api/targets/catalog`: ручной список `host` или `host,sni`, либо URL подписанного feed; POST принимает `expected_version`. GET показывает `candidates_verified:false`. До 64 кандидатов/64 КиБ payload. Подписанный envelope `{payload:base64,signature:base64}`, Ed25519 над `arcvpn-target-catalog-v1\0` + точные bytes payload. В signed payload нужны положительная `version`, будущий `expires_at`, `candidates`; `feed_version` отсутствует/0. Источник задаёт контроллер, не feed. Ключ задаётся CLI `serve --sni-catalog-key PATH` в доверенном файле; по умолчанию HTTPS update отключён.
- GET `/api/targets/nodes`; POST `/api/targets/check` `{node_id,candidates}` (1–4); GET `/api/targets/checks/{id}`. Локальная проверка возвращает результат синхронно, remote — 202 с queued/running/done/expired и последующим poll. На ноде новый агент опрашивает typed endpoint по bearer; запрос/отчёт привязаны к identity и digest, v1/expiry проверяет сам агент. `local` недоступен в agent report API.
- Максимум 2 одновременно выполняемых контроллером сетевых операций; внутри проверки 2 кандидата, 3 TCP/TLS пробы каждого, общий deadline 24 секунды. Queue: одно активное задание на ноду, до 512 записей, 120 секунд жизни, lease 45 секунд, не более 2 выдач. TTL результата 600 секунд; цифры — ограничители текущей реализации, не доказанные оптимальные значения.
- Guard отклоняет private/loopback/link-local/metadata/reserved и смешанные DNS-ответы, проверяет все ответы и соединяется с конкретным проверенным IP. TLS проверяет стандартную цепочку/имя/SNI; нет insecure режима. Успешность требует TLS1.3+h2 и HTTP2 2xx без redirect. Пригодность REALITY с конкретным Xray/клиентом отдельно не подтверждена.
- В новом VLESS подбор заполняет только пустой target; основной текущий контракт использует одинаковые target/SNI, варианты с разными именами нельзя выбрать для него. XHTTP позволяет явный выбор пары. На странице серверов можно выполнить диагностику конкретной ноды; это не меняет её конфигурацию. Существующий SNI не заменяется обновлением списка.
- Seed содержит три **непроверенных** публичных кандидата; общего «лучшего безопасного SNI» нет. Каталог и результаты не означают VPN/неотслеживаемость. Ручной ввод остаётся возможен и не получает отметку проверенного.
