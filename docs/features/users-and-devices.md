# Feature: пользователи и устройства

## Цель

Пользователь — самостоятельная сущность, не вложенный record конкретного inbound. Из одной карточки управляються все разрешённые подключения на нескольких нодах.

## Основной UI (ориентир — скриншоты 3x-ui)

Список: Summary clients/online/exhausted/near quota/disabled/active; поиск/фильтр/сортировка; колонки: status, name, group, links/profiles, used/quota, current speed, expiry, actions. Поддержать компактный режим, выбор колонок и групповые операции.

Карточка: вкладки `Основные`, `Подключения`, `Устройства`, `Учётные данные`, `Подписка`, `Статистика`, `Дополнительно`. Начать с достаточного подмножества, остальное скрыть до реализации. Базовые поля: имя, срок, старт при первом использовании, квота, сброс, группа, разрешённые подключения, статус; технические параметры — отдельно.

## Политика лимитов

- `0 = unlimited` только если чётко документировано и UI прямо подписывает это; иначе отдельный toggle «Без ограничений».
- Expiry и quota_exhausted — отдельные причины блокировки.
- Renewal/reset: фиксированное время и часовой пояс, DST и месяц с 28/29/30 днями проверяются тестами.
- Global quota между нодами может применяться с задержкой при офлайн-режиме; опубликовать границу расхождения и offline-policy.
- IP-limit не равен количеству устройств, может ложно ограничивать клиентов с мобильным IP и NAT. HWID нельзя считать доверенным аппаратным attestation.
- Device credential допускает отзыв одного устройства, но его использование может быть скопировано на другое физическое устройство.

## Ошибки и крайние случаи

- Пользователь привязан к локальному и удалённому профилю с одинаковым портом: это не конфликт, потому что IP/ноды разные.
- Отказ привязки на одной из нод не должен скрываться сообщением «Успешно»; нужен per-node результат, pending/failed и retry.
- Удаление пользователя или ротация credentials требуют подтверждения и должны отражаться в опубликованной подписке.
- Переименование пользователя не меняет его UUID и subscription identity.

## Приёмка

Создать одного пользователя и привязать к двум независимым Inbound на разных VPS; сохранить настройки; после повторного входа в UI обе привязки существуют; статус синхронизации каждой ноды правдивый; клиент видит соответствующие ссылки.
## Индивидуальные доступы локального Xray — 2026-11-05

В «Пользователи → Устройства» доступны предзаполненное добавление, отдельная подписка и отзыв. Первый доступ отключает прежний общий ключ после явного предупреждения. Лимит активных доступов находится в расширенных настройках: 0 — без тарифного ограничения. Уже выданные доступы не отзываются при уменьшении лимита: сначала нужно отозвать лишние. Имя, даты и факт отзыва показываются без секретов; подписка открывается отдельно. Один credential может быть скопирован, поэтому это не доказанное число физических устройств.

Доступы подчиняются статусу пользователя, его общему пакету и сроку; расход TCP/XHTTP суммируется на пользователя. CAS защищает изменения из нескольких окон. Сохранение и применение различаются: при ошибке службы policy сохраняется, отображается pending и выполняется повтор; живые соединения могут продолжаться до успешного применения. Backup v7 переносит устройства, старые архивы и stale v7 не отменяют местные отзывы совпадающих пользователей. Поддержка локального Xray без зарегистрированных нод и активных иных движков; UDP/remote устройства и настоящий disconnect на VPS не подтверждены.
