# Feature: подключения, протоколы, Xray

## Видимые функции

Плотная таблица: name, node, enabled, port, protocol, transport, security, clients, used traffic, speed, expiry, health. Стандартное создание через мастер; расширенные настройки Xray — отдельная вкладка.

## Начальная поддержка

P0 кодового этапа 2: VLESS + Reality TCP и XHTTP (после проверки совместимости), Hysteria2, WireGuard, AmneziaWG. Каждый движок устанавливается и запускается **только при включении соответствующего протокола**.

**Решение 2026-11-05:** текущих пяти вариантов подключения достаточно: VLESS/REALITY TCP, VLESS/REALITY XHTTP, Hysteria2, WireGuard, AmneziaWG 3.1. Этап 6 **отложен**; AnyTLS, Trojan, TUIC, Shadowsocks 2022 и экспертные overrides не разрабатывать и не показывать как поддерживаемые. Их прежний P1-план сохранён только как потенциальный будущий объём после явного решения пользователя. NaiveProxy/MASQUE не обещать как поддержку. Характеристики транспорта, SNI и сертификатов зависят от протокола; WireGuard/AmneziaWG SNI не используют. См. [scope freeze](../planning/protocol-scope-freeze-2026-11-05.md).

## Применение

- Проверка порта, bind address, TLS/Reality, прав пользователя, существующих сервисов.
- Автоматическое предложение firewall-изменения с возможностью отказа и планом отката.
- Строить config из типизированной модели и ограниченных raw overrides; запрещено произвольно переписывать user JSON без понимания его влияния.
- Dynamic API используется только для операций, реально поддерживаемых текущей версией Xray; иначе безопасная запись и контролируемая перезагрузка.
- Не перезапускать все Inbound ради изменения одного клиента без необходимости.
- Проверка внешнего подключения и IP с независимой точки, если она доступна.

## Каскады

Само добавление нового Inbound не создаёт каскад: он определяется отдельной `RoutePolicy`; хранение раздельно.

## Безопасные значения по умолчанию

Выбор порта, ключей, TLS, Reality target, транспорта и параметров скрыт от обычного пользователя, но результат показывается до применения. Нельзя выдавать «самый безопасный SNI» без проверки выбранного target. Для UDP-профилей показывать UDP-порт и отдельный внешний probe. Ограничения ресурсов и совместимость Happ/других клиентов подтверждать конкретными версиями, не предполагать универсальный импорт. Сохранить ручной override и причину его изменения.

## Реализация этапа 2 (2026-11-04)

Создание/включение/отключение одного локального профиля каждого типа: `vless-xhttp`, `hysteria2`, `wireguard`, `amneziawg`. Базовый `vless-reality` остаётся отдельным обязательным профилем. REST API: `GET/POST /api/protocols`, `PATCH/DELETE /api/protocols/{kind}`, `GET /api/protocols/health`, `GET /api/users/{id}/connections`, `GET /api/users/{id}/connections/{kind}/export` (`format=qr`). Статус `health` характеризует только локальную systemd-службу.

Реализация **не допускает произвольные поля** engine-config из UI; расширенные overrides относятся к отдельному экспертному этапу. Полные инструкции и ограничения: [runtime](../ops/protocol-runtime.md). Без проверки на реальном VPS ни один протокол не может быть объявлен E2E подтверждённым.
