# Пользовательские сценарии

## A. Первый запуск на одном VPS

Установить приложение → создать администратора, включить MFA → настроить IP HTTPS → увидеть обзор → создать VPN-подключение (VLESS/Reality) → получить firewall-правило с rollback → создать клиента → скопировать подписку Happ → подтвердить подключение и внешний IP. Агент не нужен.

## B. Новый сервер через UI

Серверы → Добавить → адрес/SSH user/port/auth → проверить host key и доступ → показать план изменений → установить агент/Xray → проверить API связи и публичный VPN-вход → назначить роль «независимый/вход/выход/резерв» → опубликовать рабочий endpoint в подписке. Отказ любого шага: понятная ошибка и безопасное повторение.

## C. Каскад

Маршруты → Создать → выбрать `вход A` и `выход B`, без предположения о стране → опционально `резерв C` → режим fail-closed → предпросмотр создаваемых inbound/outbound/firewall → тест фактического egress → применить. Возможна обратная последовательность B → A.

## D. Резервирование

Основной выход теряет работоспособность → несколько проверок подтверждают сбой → новые соединения через резервный exit → администратор видит кто/что/когда переключилось; старые сессии могут оборваться. После восстановления обратный переход с cooldown и проверками.

## E. Замена входного VPS

Найти logical endpoint → «Заменить сервер» → зарегистрировать новый VPS → подготовить его с сохранением совместимых параметров → health test → заменить публикацию в подписке → проверить новые подключения → архивировать старую ноду. Если сам URL подписки утрачен, использовать резервный канал, заранее известный клиенту.

## F. Пользователи

Создать пользователя, срок, квоту, доступ к нескольким Inbound/узлам → показать доступные протоколы и QR → привязать дополнительное подключение без второго пользователя → управлять отдельными credentials устройств и статусом. Не помещать все параметры Xray в основные поля.
