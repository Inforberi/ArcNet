# ArcVPN — этап 5: маршруты, каскады, резервирование

**Точка входа:** `0.7.0-stage5-foundation` (2026-11-05). Это **основа для Codex**, а не приёмка этапа 5.
См. [фактические исходники и границы](../release-0.7.0-stage5-foundation.md).

## Выполнено в текущей основе (тесты см. в протоколе)

- [x] S5-01. Типизированная `RoutePolicy`: `direct` или `cascade`, направление задаётся явно и не зависит от региона.
- [x] S5-02. До четырёх резервных выходов; повторяющиеся узлы/самопетли запрещены.
- [x] S5-03. Проверка графа **всех** черновиков, включая резервные рёбра, с обнаружением циклов.
- [x] S5-04. Сохранение в SQLite с аддитивной миграцией и optimistic concurrency (версия).
- [x] S5-05. Проверка, что ID участвующих VPS существуют; `local` — специальная логическая запись локального контроллера.
- [x] S5-06. Read-only preview с графом и изменениями; без операций на нодах.
- [x] S5-07. Сессия, CSRF и аудит операций создания, редактирования, удаления; сервер не публикует неподтверждённый маршрут.
- [x] S5-08. Чистый симулятор с fail-closed, порогами отказов/восстановления и cooldown, где `unknown` не приравнен к `healthy`.
- [x] S5-09. Базовый React UI создания, редактирования, предпросмотра, списка, удаления и симуляции черновиков.
- [x] S5-10. Unit/Store/HTTP тесты модели и контуров доступа, общий `go test ./...` и `go vet`.

## Нереализованная функциональность этапа 5 (Codex / следующая кодовая работа)

- [ ] S5-11. Формальная модель `LogicalEndpoint` и независимый от конкретного VPS идентификатор точки подключения, привязка к inbound и пользователям.
- [ ] S5-12. Выделенный межнодовый канал: независимые credentials, ограничение доступа по назначению, ротация без потери пользовательских секретов.
- [ ] S5-13. Проверенные генераторы Xray: outbound входной ноды, межнодовый inbound выхода, tagging, routing, balancer и правила безопасности. **Без произвольных shell-команд.**
- [ ] S5-14. Подготовка изменений на выходах перед входом, валидация `xray run -test`, персистентные multi-node операции, per-node ACK, compensation/rollback к last-good.
- [ ] S5-15. Идемпотентное восстановление операций при рестарте контроллера и обрыве связи; reconcile ревизий и учет частично применённых конфигураций.
- [ ] S5-16. Data-plane контроль TCP/UDP на реальных клиентах, привязанный к route revision и фактическому exit IP. Нельзя объявлять health только по heartbeat.
- [ ] S5-17. Реальный failover новых подключений с hysteresis/cooldown на наблюдениях из доверенных независимых проб, без обхода напрямую при fail-closed.
- [ ] S5-18. Безопасная публикация `SubscriptionRevision` **после** применённых ревизий всех нод и успешных egress-проб; отзыв при потере достоверности.
- [ ] S5-19. Поддержка настоящих логических схем, включая ingress offline, egress offline, reverse A→B/B→A, локальный direct, удалённый direct, 3 узла.
- [ ] S5-20. Для draft-состояния реализован encrypted backup v4, атомарный restore, CAS и тесты гонок сохранения/удаления нод. Runtime state, конкурентные failover/apply и crash/fault-injection ещё не реализованы.
- [x] S5-21a. Реальный npm lockfile, `npm ci`, TypeScript, Vite production, новый `tests/routing_e2e.mjs` на 320/390/768/1024/1440 px и двух темах — [протокол](../testing/local-results/stage5-2026-11-05-routing-ui.md).
- [ ] S5-21b. Прежний `tests/react_e2e.py` и полный Linux x86_64 release pipeline ещё не прогнаны в этом блоке; не подменять их новым отдельным UI-тестом.
- [ ] S5-22. Внешняя проверка двух и трёх VPS, сбоя входа/выхода, обрыва TCP-сессии, UDP/VLESS/Happ и фактического egress IP.
- [ ] S5-23. Актуализировать threat model и матрицу поддерживаемых версий Xray с результатами внешних тестов.

## Условия приёмки

`S5_DRAFT_CONTROL_PASS` подтверждает только модель, сохранение и симуляцию. `STAGE5_ACCEPTED` возможен только после S5-11…S5-23 с фактическими журналами, изменением Xray, проверенным exit IP и тестами отказов. Не подменять эти статусы.

Этап 4 (`0.6.5`) остаётся `EXTERNAL_PENDING`, включая React build, VPS и отдельный долг SSH-hardening этапа 3. Начало реализации этапа 5 не изменяет его статус.
