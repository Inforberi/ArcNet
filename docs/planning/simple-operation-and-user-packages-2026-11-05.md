# Простой сценарий, пакеты трафика и устройства

Решение пользователя 2026-11-05. Приоритет — корректность уже выбранных пяти протоколов, каскадов и восстановления. VPS пользователь предоставит после подготовки локального кода. Этот документ фиксирует требования и остаток; не является приёмкой runtime.

## Обычный сценарий

Выбрать способ подключения → получить заполненные параметры и краткое описание → создать. Обязательного предварительного мастера настроек нет. Адрес берётся из доверенной конфигурации панели/сервера, порт — с учётом существующих назначений. Неподтверждённые свободный порт/сертификат/доступность не называются проверенными. Для Reality рекомендации основаны на свежих проверках с выбранного сервера; это не измерение устойчивости к DPI или VPN-handshake.

Ручной ввод сохраняется при приходе автоматической рекомендации, обновлении данных и временном переключении типа подключения. Можно вернуть автоматические значения. Расширенные параметры существующих функций доступны через UI; произвольные raw overrides и stage6 этим решением не вводятся. Новые компоненты используют `shared/ui`, а страница компонует формы, данные и действия.

Независимое первое создание TCP REALITY/XHTTP/Hysteria2/WireGuard реализовано локально 2026-11-06: [ADR-012](../adr/012-independent-first-local-protocol.md), [проверки](../testing/local-results/stage5-2026-11-06-first-protocol.md). Адрес локального сервера отделён от TCP-listener; скрытого VLESS нет. AmneziaWG исключён из дальнейшего объёма, старые данные сохраняются.

## Мониторинг

По умолчанию 5 секунд. Общая настройка 5/10/15/30/60 в расширенном UI, сохранение на сервере. Одна подписка в авторизованном layout, переподключение, приостановка скрытой вкладки, резервный опрос при недоступности stream. Расписание ресурсов отдельно от heartbeat, установки, применения конфигов и VPN-проб. Старый агент честно остаётся со своей прежней частотой.

## Пакет пользователя

Пользователь уточнил: «списание» означает расход гигабайтов пакета, **не деньги и не баланс**. Реализован первый локальный контур Xray: [ADR-008](../adr/008-local-xray-traffic-packages.md), отдельные доступы устройств: [ADR-009](../adr/009-device-credentials.md). Остальные движки/ноды пока не поддержаны; VPS исполнения нет. Ниже полный целевой контракт.

- Карточка/таблица: передано, получено, использовано из пакета, осталось, период/срок, статус источника учёта и время последнего отчёта. Неизвестный расход — «Нет данных», а не 0.
- По умолчанию учитывать сумму пользовательского upload+download; явно показывать единицы (ГБ = 10^9 байт). Счётчики ОС не являются счётчиками пользователя.
- Источник — поддерживаемый API/контролируемый адаптер конкретного движка: Xray, Hysteria2, WireGuard, AmneziaWG. До интеграции и теста конкретного источника не показывать работающий лимит этого протокола.
- Персистентный журнал приращений с привязкой к пользователю, credential, движку, ноде, эпохе счётчика и порядку наблюдения. Повтор отчёта не списывает байты второй раз. Reset/restart, старый отчёт, смена идентичности и восстановление backup не приводят к повторному списанию или тихому обнулению пакета. Пробел в наблюдениях отображается явно.
- В каскаде считать клиентский расход на выбранной точке учёта один раз; межнодовый участок не списывать повторно. При переключении/переезде сохранять журнал и владение счётчиком.
- Конечный пакет, продление/явный сброс с аудитом, срок и причина блокировки. По умолчанию пакет не ограничен; ограниченный пакет нельзя объявить действующим, пока нет подтверждения его исполнения во всех выданных подключениях.
- При исчерпании — отозвать доступ на всех назначенных нодах с per-node ACK/ошибками и повторным восстановлением после обрыва. Показать фактическую задержку/допустимый перерасход; не обещать точность до байта при распределённом опросе.

## Устройства

Ограничение зарегистрированных подключений: отдельная credential на устройство, наименование, выдача/отзыв одного устройства, общий пакет пользователя. IP-count, online-count и число выданных credentials — разные показатели. HWID клиента не является аппаратной аттестацией; копирование ключа физически не исключается.

В текущем локальном Xray блоке общий credential остаётся до первого добавления устройства. Затем он отключается после явного UI-предупреждения; исходный UUID пользователя не ротируется, но прежняя подписка больше не выдаёт доступ. Это необходимо для исключения обхода через общий ключ. Есть индивидуальные подписки и encrypted backup v7. Отдельные WireGuard/AWG peer/IP на устройство и remote credentials остаются следующими блоками. Нельзя выдавать SQLite policy или успешное сохранение за подтверждённый отзыв живого VPN-соединения.

## Порядок оставшейся реализации

1. Локальная независимая identity/первый протокол и восстановление реализованы (ADR-012); реальные systemd/handshake/отказы ещё требуют приёмки.
2. Пользователь/устройство/credential, адаптеры учёта движков, журнал расхода и пакет; затем исполнение/отзыв во всех профилях и нодах.
3. LogicalEndpoint, отдельные межнодовые credentials, генераторы каскада, staged multi-node apply/ACK/reconcile/rollback; независимая egress-проба и отдельный publish.
4. Геоправила, серверный failover и клиентское переключение по согласованным контрактам; не путать эти три функции.
5. VPS/systemd/UFW/ACME/handshake, реальные расходы/отзывы, частичные сбои, restore и длительные испытания. Только после фактических результатов — ACCEPTED.

Для каждого блока обязательны тесты restart/replay/concurrency/fault/restore и обновление текущего статуса. Утверждение «без сбоев» не заменяет результаты этих испытаний.
