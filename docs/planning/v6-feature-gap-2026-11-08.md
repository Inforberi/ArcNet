# ArcNet v6/v7: перенос интерфейса и функциональности

Дата: 8 ноября 2026. Источник дизайна: пользовательский ArcNet_VPN_Admin_v6.zip. Сверка — исходники текущего рабочего дерева; не аудит установленной VPS-версии. Документы/API из архива — предложения, не существующие контракты ArcNet.

## Актуализация v7 — 8 ноября

Источник визуала и поведения: пользовательский ArcNet_VPN_Admin_v7.zip, включая source/arcnet_v7.js и README v7.1. Демонстрационные storage/API/ключи не являются реализацией сервера. Ниже исходная матрица gap сохранена как исторический baseline; текущий статус — здесь и в [current-task](../ai/current-task.md).

- Локально реализованы: DS тёмной темы, общие диалоги/QR, пользовательские metadata/назначения, единый editor/bulk/CSV, расписания и трафик из существующего сбора; текущая source-проверка не означает VPS acceptance.
- Перенесены настройки v7 «Простой / Расширенный»: выбор в браузере, раскрытие общих дополнительных настроек, основные пакет/срок/автосброс пользователя на виду; секретная ссылка раскрывается отдельно.
- Typed настройки TCP flow/sniffing, XHTTP mode/path/fingerprint, WG client MTU/DNS/keepalive, Hysteria timeout/Salamander/Brutal и rotation REALITY/WG проведены до runtime/export/backup18. Это не все поля демо.
- Остаются: дополнительные typed listen/Host/ALPN и другие поддерживаемые поля, несколько подключений одного вида с миграцией, полноценный proposal параметров, source/enforcement IP-сессий, firewall/WG реальная приёмка, единая защита/логи нод, full updater, прочие внутренние экраны и визуальная/mobile проверка. Дополнительные протоколы демо не входят в замороженный scope. Каскады после базового сценария.

## Порядок законченных блоков

1. Дизайн-система v6 + реальные существующие функции: навигация, обзор, версии/настройки, чтение пользователей и подключений. Локальный просмотр до выпуска.
2. Цельный редактор пользователя: metadata, пакет/срок, назначения, режим выдачи, связанные изменения backup/API/runtime. Ни один переключатель не считается готовым без серверного исполнения.
3. Управление набором подключений и расширенные typed настройки; отдельное решение/миграция connection ID до поддержки дублей. WG/XHTTP исправить и подтвердить независимо от дизайна.
4. Безопасный подбор/обновление параметров и согласование firewall; обязательные model-of-threat/isolated VM rollback gates сохраняются.
5. Пользовательская телеметрия, наблюдения сессий, массовые сценарии и расписания сброса отдельными ограниченными блоками; не изображать их online до фактической реализации.

## Минимальные критерии проверки

- Назначение/отзыв влияет на действительный доступ, а не только на видимость URI; device/export/QR не обходят запрет.
- Metadata/режим выдачи не меняют UUID/ключи и не перезапускают engine без причины.
- Восстановление backup сохраняет назначения, режимы, параметры, расписания и identities; миграция не теряет старые токены.
- Расписание не списывает/сбрасывает дважды после повторного запуска; expiry не продлевается; неполный учёт не скрывается.
- Обновление подключения не применяет устаревший plan, показывает область влияния; ошибки runtime/UFW откатываются.
- График и онлайн имеют источник, интервал свежести и честный missing state; история трафика не становится списком «списаний».
- Desktop/mobile, 200% zoom, keyboard, long labels и overlays проверяются через общие компоненты. Сетевые тесты отдельно; docs-only сверка не требует новой сборки.

Проверено чтением User, Package, Protocol, credential schemas, userPatch, маршрутов API и UI-компонентов. Изменений приложения/БД/VPS в этом блоке нет.

## Уточнение владельца после просмотра

В обычном UI не должно быть ручного «Добавить устройство»: нужны ограничения/наблюдения устройств или IP. Кнопка и автоматический переход с shared credential убраны из экрана; уже выданные credentials сохраняются и остаются доступны для отзыва/подключения. Лимит credentials не переименовывать в лимит физических устройств. Настоящее concurrent enforcement остаётся отдельным backend-блоком. Уточнение заменяет более раннюю рекомендацию сохранять ручное создание как обычный сценарий.

## Реализованный исходный блок: preferences и local assignments

Редактирование имени/группы/комментария/custom subscription title, preferred выдача и local allowed kinds реализованы в UI/API/SQLite/engine render/exports/backup14. Список назначений ограничен local-only без нод и pending enrollments; remote policy ACK требует отдельного блока. Пакет/срок пока отдельная вкладка, общего Save нет. [Контракт](../features/user-preferences.md), [реальные проверки](../testing/local-results/user-preferences-2026-11-08.md). Это не выполнение всей матрицы.

### Единый редактор / bulk access — реализовано локально
Имя, access, подписка/выбор протоколов, пакет/срок и reset имеют одно атомарное сохранение с CAS; bulk enable/disable до100 выбранных строк. При runtime failure показывается pending, worker повторяет. Отдельные scheduler/IP limits/online/графики/mass create не реализованы. См. [контракт](../features/user-preferences.md#единый-редактор-и-массовый-доступ). VPS/релиз не менялись; визуальная приёмка открыта.

### Таблица и расписания — продолжение
Реализованы сортировка/группы/CSV и массовое создание/пакеты/сроки/назначения; ежедневный/еженедельный/ежемесячный reset с IANA, свежестью, catch-up и backup15. Смотри [контракт](../features/user-preferences.md#таблица-и-массовые-сценарии--продолжение-8-ноября). Телеметрия/online/IP limits, полный connection editor/connection ID, proposal параметров, firewall/full updater и визуальная приёмка остальных экранов остаются открыты. Проверки логики не заменяют runtime приёмку.

### Пользовательская телеметрия — локальный блок
Скорость, график, наблюдаемый рост счётчиков и one-batch polling реализованы для поддерживаемых локальных движков. RAM history bounded/эфемерна, online не выводится из трафика и пока unknown. Наблюдаемые сессии/IP и remote telemetry ещё не реализованы. [Контракт](../features/user-traffic.md).
