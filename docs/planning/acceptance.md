## Нагрузочный профиль для первичной оценки

Малый VPS с 1 vCPU/1 ГБ, один Go и один Xray, 100 созданных пользователей, 10 активных VPN-клиентов и одно браузерное соединение администратора. Это план теста, а не обещание, что один сервер выдержит любой трафик. Измерять частоты/память/сокеты при разных профилях и отдельно учитывать ОС.

## Метрики

RSS обоих процессов и system total memory, CPU по процессам и системы, p50/p95 Go API, SQLite write latency, потеря/откат ревизий, задержка detection/ failover, время установки, стабильность TLS renewal. Пороговые значения фиксировать после первого прототипа; нельзя выбирать их задним числом как «успешные».

## Дополнительные критерии приёмки по дополненным требованиям

| ID | Сценарий | Проверяемый результат |
|---|---|---|
| AC-21 | Новый чистый VPS: SSH installer из UI | host key проверен, preflight полный, секреты не сохранены, Xray/agent healthy, внешний пробный VPN handshake |
| AC-22 | Сервер с занятым VPN-портом | Чужой процесс не остановлен, UI предлагает другое допустимое значение и объясняет конфликт |
| AC-23 | Автоматическая настройка из простого UI | Система создаёт inbound/credentials/managed firewall/subscription без raw JSON |
| AC-24 | Ручной override порта или transport | Видно происхождение настройки, rollout не стирает override без предупреждения |
| AC-25 | Переключить «Схема» ↔ «Таблица» | Сохраняются выбранная нода, маршрут, фильтры, признаки ошибки и timestamp |
| AC-26 | Обратное направление каскада | Нет привязки к стране и не нужно пересоздавать пользователей |
| AC-27 | Ложный heartbeat-успех при сломанном VPN | UI показывает agent online, Xray/VPN/route unhealthy отдельно |
| AC-28 | Отключить HTTPS, SSH или изменить firewall опасным способом | Требуется plan/confirmation + независимый probe/rollback, нельзя молча потерять доступ |
| AC-29 | Восстановить после прерванной установки | Операция возобновляется или безопасно откатывается без двойной регистрации/ключей |
| AC-30 | Компрометация одного node key | Отзыв изолирует ноду; другие ноды сохраняют собственную идентичность |
| AC-31 | Один VPS 1 vCPU/1 GB, простой UI и dashboard | Замеры system total memory+CPU, нет обязательного Node.js/Redis/Podman; бюджет подтверждается или статус «не достигнут» |
| AC-32 | Обновление IP endpoint без домена | Сервис подписок отдаёт новый IP и клиент обновляется при доступном URL; невозможно обещать восстановление при потере всех URL |
| AC-33 | HTTPS панели и Xray на одном IP претендуют на 443 | Preflight обнаруживает конфликт, предлагает безопасную схему, не меняет действующие службы без подтверждения |

## Дополнительные обязательные приёмочные сценарии (из уточнённого ТЗ)

| ID | Сценарий | Критерий и среда |
|---|---|---|
| AC-34 | Одна нода без каскада, второй VPS не требуется | Внешнее VPN-подключение проходит через автономный VPS; проверяется на тестовом VPS |
| AC-35 | VLESS доступен клиенту, Hysteria2 заблокирован в его сети | Нет ложного глобального переключения всех пользователей по серверному RTT; клиент получает совместимые резервные профили, подтверждается из клиентской сети |
| AC-36 | Перенос ArcVPN → ArcVPN через UI | После переноса на второй VPS сохраняются ID пользователей/подписок, ключи и конфигурации, некорректный архив не вносит частичных изменений |
| AC-37 | Управляемые логи панели, Xray и journald | Размер и очистка контролируются в пределах управляемых журналов, чужие службы ОС не затронуты |
| AC-38 | Тёмная и светлая темы React через cookie | Reload/новая вкладка/адаптив 320/390/768/1024/1440, keyboard и реальный HTTPS-auth |
| AC-39 | Установка удалённой ноды из UI или одноразовой командой | Чистый VPS регистрируется, поднимает VPN-движок, публикуется только после внешнего пробного подключения |
| AC-40 | Установщик, меню и восстановление пароля | На чистом Debian/Ubuntu: установка одной командой, CLI password reset с отзывом сессий, повторный запуск не ломает состояние |

**Правило доказательств:** `ACCEPTED` только после локальных и внешних проверок, где они требуются. Программирование следующих компонентов допустимо при `LOCAL_PASS / EXTERNAL_PENDING`, но промежуточный ZIP нельзя сдавать как production. Внешние отчёты хранить в `docs/testing/external-results/`.
