# Что выполняем в чате, а что отдаём Codex на VPS

**Правило:** **код может быть написан и проверить его можно частично здесь**, а **реальное сетевое и системное поведение** требует специально подготовленного стенда. Существование исходника, успешная компиляция или имитация HTTP **не доказывают** работу VPN в сети.

## 1. Матрица возможностей

Легенда: **Здесь** — код/локальные тесты возможны в доступном контейнере при наличии зависимостей; **Codex** — проверки на отдельной машине/VM/VPS.

| Подсистема | Здесь: делаем и проверяем | Codex: обязательные внешние проверки |
|---|---|---|
| Go API, SQLite | Всё прикладное поведение, транзакции, гонки, миграции, auth, лимиты, ошибки, тестовые данные | Поведение после systemd restart, reboot, дисковых сбоев, права каталогов на реальной ОС |
| React UI | Пишем TS/React/CSS, статические проверки, сборку и браузерные тесты **когда доступны npm/браузер**; контракты с Go через HTTP fixtures | Сборка из чистого lockfile, E2E с настоящим API, адаптивы 320/390/768/1024/1440, keyboard/a11y, реальные TLS-cookie |
| Xray и протоколы | Формируем конфигурации, делаем validation, сравнение и rollback, подготавливаем engine adapters, тестируем состояние и ошибки | Реальный Xray/Hysteria/WireGuard/AmneziaWG, внешний TCP/UDP клиент, egress IP, нагрузка, ограничения ОС и клиента |
| Node enrollment и агенты | Подписи/токены/mTLS и protocol tests, heartbeat, last-good, versioning, retry, тесты обрыва связи | SSH host key, systemd на ноде, firewall, сетевые потери, bootstrap с внешнего IP |
| Каскады/отказы | Граф, модель ресурсов, state machine, план и atomic apply, mock fault injection, граничные случаи | Минимум два VPS, маршрут A→B и B→A, блокировки UDP/TCP, тест с отдельного клиента, реальные задержки |
| Установщик, systemd, firewall | Реализуем bash/Go, shellcheck при наличии, `bash -n`, проверки dry-run и недеструктивные unit tests | Чистая VM/VPS с rescue console, идемпотентность, UFW/SSH rollback, порт 443, удаление/обновление |
| HTTPS по IP | Реализуем ACME flow, ограничения доступа и renewal, тестируем TLS логику на test CA | Реальный выпуск/продление сертификата для публичного IP и соединение без `-k` |
| Логи 500 МиБ | Реализуем отдельные лимиты панели, Xray и управляемого journald с аудитом, тесты ротации на временных файлах | Поведение logrotate/systemd на VPS, реальный рост логов, отсутствие потерь важных записей |
| Резервные копии и перенос | Формат архива, шифрование, versioning, restore dry-run, целостность, сохранение client/subscription IDs | Полное восстановление на новом VPS, перенос ключей/маршрутов, учёт нового IP, проверка работоспособности клиентов |
| Безопасность | Модель угроз, auth/CSRF/SSRF/secret leakage, права API, негативные сценарии, анализ зависимостей | Тест привилегий на ОС, открытые порты, TLS, firewall, реальная компрометация/отзыв агента |
| 1 vCPU / 1 ГБ | Профилировка Go, локальные бенчмарки и ограничения конкуренции | Повторяемый benchmark на целевом VPS и отчёт memory/CPU/Xray/OS |

**Ограничение среды на момент составления:** Go и Node/npm доступны, но в полученном исходном архиве нет `frontend/node_modules` и `frontend/package-lock.json`; предыдущая попытка скачивания пакетов через npm не удалась. Запуск `npm ci` **сейчас невозможен без lockfile**. Нужно получить воспроизводимую сборку в окружении с сетевым доступом, зафиксировать lockfile и по возможности затем повторять её здесь. Не называем проверку синтаксиса TSX полноценной сборкой.

## 2. Статусы работ и проверок

| Статус | Смысл | Можно передавать как production? |
|---|---|---|
| `PLANNED` | Функция только описана | Нет |
| `IMPLEMENTING` | Код неполный/в процессе | Нет |
| `LOCAL_PASS` | Код завершён, все **доступные** локальные тесты проведены; известные ограничения перечислены | Нет |
| `EXTERNAL_PENDING` | Готово воспроизводимое задание для внешнего теста, доказательств пока нет | Нет |
| `FAILED` | Обнаружен дефект; указаны шаги воспроизведения | Нет |
| `ACCEPTED` | Локальные и обязательные внешние проверки прошли, есть доказательства | Можно рассматривать для релиза в рамках полного релизного gate |

Запрещены промежуточные формулировки «практически production», если остался `EXTERNAL_PENDING`.

## 3. Минимальная цена проверок

- На каждом изменении: `go test ./...`, `go vet ./...`, проверка изменённых TS-файлов с `tsc` **если зависимости доступны**, `npm run build` **если доступен lockfile**, и `bash -n` для изменённых shell scripts.
- При изменениях безопасности, конкурентности, миграций, конфигураций, подписок или привилегий — точечные негативные/интеграционные тесты (нельзя отложить на конец проекта).
- Расширенные `race`, UI E2E, тесты производительности/отказов — на завершающей проверке этапа и в Codex, если среда не позволяет их запустить здесь.
- Не запускать опасные SSH/UFW/systemd-команды в текущем контейнере и не проверять установщик на рабочем VPN пользователя.

## 4. Передача Codex

Для каждого внешнего сценария создавать запись в `docs/testing/external-results/` (можно пустой каталог с `.gitkeep`), содержащую: commit SHA, OS, архитектуру, версии движков, команды без секретов, ожидаемое/фактическое, exit code, санитизированный лог, скриншоты, замечания, rollback. Пример и готовый протокол — [`codex-handoff.md`](../testing/codex-handoff.md).

**Примечание:** Codex сам по себе не является доказательством. Доказательством является фактически выполненный сценарий на подходящей машине с сохранённым результатом.
