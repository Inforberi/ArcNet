# 0.7.0 stage5: мониторинг по подписке и простые формы

2026-11-05. Локальный блок исходников; не production release и не приёмка этапов 4–5.

Реализованы общий интервал 5 секунд по умолчанию, сохраняемый выбор 5/10/15/30/60 через расширенный UI, одна SSE-подписка авторизованной панели, reconnect/offline/online/watchdog и резервный опрос. Скрытая вкладка закрывает подписку. Collector и ресурсная телеметрия нового агента следуют общей настройке; apply/heartbeat/VPN probe не меняют частоту. Старым агентам/контроллерам оставлен совместимый режим. Ошибка истории не маскирует доступные текущие показатели. Состояние systemctl кэшируется пять секунд для всех вкладок.

`VPN` компонует отдельные `RealitySetup`/`ProtocolSetup` из дизайн-системы. Доверенный адрес и порт предлагаются API, Reality-кандидаты проверяются автоматически. Расширенные поля свёрнуты, ручные значения и отдельные drafts протоколов сохраняются, можно вернуть автоматический режим. Нет подстановки непроверенного «самого безопасного SNI», публичных приватных ключей или автоприменения действующей конфигурации. Создание остаётся явным действием.

Контракт и архитектура: [ADR-007](adr/007-live-monitoring-and-simple-connection-forms.md). [Фактические результаты](testing/local-results/stage5-2026-11-05-live-monitoring.md).

## Остаток

Пользователь подтвердил пакеты трафика с расходом гигабайтов, без денежного биллинга, и управление устройствами. Реальный per-user accounting/списание, quota enforcement, per-device credentials, первый запуск любого протокола без обязательного базового VLESS, runtime каскадов/failover/publish **ещё не реализованы**. Согласованный порядок и инварианты: [план](planning/simple-operation-and-user-packages-2026-11-05.md). Никаких декоративных «работающих лимитов» в UI не добавлено.

VPS пользователь предоставит позднее. Реальные VPN/systemd/UFW/SSH/ACME, 2–3 VPS и независимый egress не проверены. История остаётся минутной до двух часов; обновление текущего снимка 5 секунд не означает пятисекундную детализацию графика. Изменение частоты удалённый агент получит при следующем отчёте; обновление бинарника старого агента требуется отдельно.
